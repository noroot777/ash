# 验收前置命令的源码与运行凭据

项目的 `acceptGateCommand` 在点验收时执行。目标分支不存在、被其它 worktree 占用、目标工作区不干净或依赖尚未就绪等廉价检查先运行；测试通过后真正合并前仍重新检查。

## 被测源码

Git 项目先要求任务工作区的索引和工作树干净，包括未跟踪文件。测试不再在该工作区直接执行，而是在独立 clone 的 detached 提交上执行。该 clone 不共享可写工作树、索引、refs 或 Git 对象硬链接，也不保留指向原工作区的 remote。

快照提供已提交文件，以及根目录、已提交包清单（`package.json`、`pyproject.toml`、`Cargo.toml`、`go.mod`、`composer.json`、`Gemfile`）所在目录中现有的 `node_modules`、`.venv`、`vendor`、`target`。依赖独立复制，不保留指向原工作区的可写链接；实际复制的普通文件内容参与源码指纹。依赖树中的环和断链按相同规则从指纹及副本中剪除，不因一个不可用的 `.bin` 链接拒绝整棵树。其它被 Git 忽略的文件（例如 `.env`、本地数据库和自定义依赖目录）不自动复制。需要这些内容的命令可能失败，可将可复现输入纳入版本管理，或明确决定本次跳过。复制虚拟环境不等于重写内部绝对路径，也不保证它可跨机器运行。Git 子模块及指向快照外的源码符号链接目前拒绝运行，而不是借用原工作区内容。

命令产生的未跟踪构建产物只留在快照里。Windows/Linux 在整次进程退出被证实后删除快照；macOS 兼容监督保留快照，避免把观察范围内的退出误当作所有后代退出而删除目录。命令修改已提交源码或改动快照的 HEAD 时，即使退出码为 0 也不放行。非 Git 项目复制普通文件与目录，以内容指纹和起跑输入清单核对；原目录输入变化会使结果过期，测试修改原有输入不会为原目录放行，快照内新生成的构建产物不影响原输入身份。

这是执行前后的源码一致性校验，不是恶意命令沙箱或逐次写入审计：命令修改源码后恢复原字节且 HEAD 不变，结束时的检查无法发现这段历史。未提交/未跟踪源码的拒绝是可复用提交凭据的边界，不会自动提交、删除或忽略这些文件。

复用依据为命令、源码提交和输入指纹；自动续验收、手动复用、批量预判与状态新鲜度共用这一判据。旧的仅有提交号的结果不再复用。真正的 Git 合并读取被测提交号，而不是再次解析可变的任务分支；分支不再指向该提交时拒绝合并。目标分支前进后的非 fast-forward 合并仍只记录被测范围，不宣称测过最终合并结果。

## 进程能力与恢复

门禁命令在启动器的监督归属登记完成后才获得执行许可。Windows/Linux 使用整次运行的内核退出证据；macOS 使用下述明确分档的兼容监督，不把它标成内核围栏或整次运行证明。

- Windows 使用门禁专属的独立 Job supervisor，在实际打开的进程句柄上核对创建时间，再用同一句柄加入 Job，持久化带代际的归属与集合为空的终结凭据。编译及等待登记使用异步路径，不再同步冻结服务事件循环。服务进程退出后仍可以恢复查询；Job 名字不存在但没有终结凭据时不放行。
- Linux 使用可写的 cgroup v2；无法建立或恢复集合时拒绝授权或保留停止责任。
- macOS 实际执行同一条验收命令，使用 `macos-observed` 兼容监督：原生读取进程组、父子关系、微秒级启动身份与 `KERN_PROCARGS2` 的 NUL 分隔环境项，精确匹配每次运行的继承标记；观察到的成员身份落盘并定期刷新。取消、超时、正常结束和服务重启后的恢复都先收尾这些进程，每次发信号前重新核验启动身份，不根据 `ps` 的环境展示文本杀进程。监督读取失败会保留占用，不按退出处理。

macOS 仍没有等价 cgroup/Job 的完整保证：在两次观察之间出生、清空标记并脱离进程组的后代可能无法识别，兼容模式不宣称覆盖它们。通过表示命令 rc=0、已识别进程收尾完成且源码核对通过；启动记录持久化 `observed-empty` 而非 `kernel-empty`，验收卡、日志及时间线均显示这一范围。测试快照不自动删除，路径保留在日志中；这会占用磁盘，也不代表不可识别的后代已退出。编译原生监督器需要本机 Xcode Command Line Tools（`/usr/bin/clang`）；编译失败按实际启动失败处理，不会跳过测试或改写项目命令。旧 macOS 记录缺少这一监督身份时仍保留原有停止保护，不会仅因升级就放行。

缺失新字段但已持久化 `armed` 和内核归属的旧记录，会在能重新查询真实集合时补录登记凭据；集合消失仍不冒充空集合。无法恢复的记录继续阻挡合并与清理，取消后可在两处门禁卡展开“确认风险并强制释放”。该动作需要指定运行 ID 和二次明确确认，持久化为 `interrupted/ownership_waived`，写入日志与时间线，清空可复用源码身份，保留独立快照，不向身份不明的 PID 发信号。它只是人工放弃停止保护，不是内核退出证明或测试通过；残留进程仍可能写文件，后续合并、删除与接力可能有风险。重复确认幂等，保存失败则保留占用。单个根进程退出仍不会自动核销责任。取消时若终态写入失败，响应为 `settlement_failed`，界面提示重试；运行占用与未结算状态继续保留，避免显示“已经结束”。

Git 快照复制时同时计算副本指纹，省去复制前和复制后对依赖的两次额外完整重读；验收判定与复制后的原输入仍完整核对。状态新鲜度查询也保持内容校验，大依赖树仍有 IO 成本，没有用陈旧缓存替代真正验收判据。批量预判在本机能力或源码输入不可用时不会谎报“即将起跑”。

macOS 的独立原生 guardian 在授权前加入启动器的进程组与会话，微秒级身份随监督记录持久化；它在命令父进程退出后继续锚定这一组的代际。因此清空环境但没有脱组的后代仍会被纳入收尾，不依赖恰好赶上一次采样。组成员由原生进程组查询补核，成员不可读或组代际无法确认时保留占用，不向可能复用的组盲发信号。整组及已识别成员收尾后关闭这一代际，再结束 guardian；显式强制释放在保存成功后销毁扫描器和自己的 guardian，不把放弃责任写成退出证明。较旧的观察记录缺少 guardian 凭据时不自动升级为新证明。

## 跨机接力

导出与移回携带冻结的验收方式、凭据运行 ID 和已结束的门禁历史；日志通过普通运行产物搬运。PID、内核集合、启动控制文件、测试快照和自动续验收选项不跨机携带，仍有停止责任的运行阻止接力。附件预览与导出共用运行产物枚举器，在递归前排除保留快照与监督文件，不读取快照依赖里的文本或把其中的路径算成待迁移附件。

导入将运行记录和日志地址映射为本机路径；移回时事务性替换历史，重复同一次传输保持幂等。迁入记录只证明历史，不直接作为当前机器重跑或复用的凭据。日志超限未携带或已被清理时，界面明确显示“当前不可查”，日志接口也不把缺失冒充为空日志。

## 回归入口

- `npm -w server run test:accept-merge`：合并、门禁编排、源码身份与生产进程能力测试。
- `npm -w server run test:handoff-accepted-return`：已验收任务移回、门禁凭据与日志双向接力。
- `npm -w web run test:accept-gate-dom`：真实无头浏览器中的取消失败反馈和日志缺失提示。

POSIX 上的编排回归使用仅存在于测试启动器中的进程组夹具，不代表生产围栏可用；生产进程、detached 后代和跨控制进程恢复用例独立运行，不加载该夹具。
