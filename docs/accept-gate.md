# 验收前置命令的源码与运行凭据

项目的 `acceptGateCommand` 在点验收时执行。目标分支不存在、被其它 worktree 占用、目标工作区不干净或依赖尚未就绪等廉价检查先运行；测试通过后真正合并前仍重新检查。

## 被测源码

Git 项目先要求任务工作区的索引和工作树干净，包括未跟踪文件。测试不再在该工作区直接执行，而是在独立 clone 的 detached 提交上执行。该 clone 不共享可写工作树、索引、refs 或 Git 对象硬链接，也不保留指向原工作区的 remote。

快照只提供已提交文件，以及根目录、已提交 `package.json` 所在目录中现有的 `node_modules`。依赖独立复制，不使用指向原工作区的可写链接；依赖内容参与源码指纹。其它被 Git 忽略的文件（例如 `.env`、本地数据库和构建缓存）不自动复制。需要这些内容的命令可能失败，可将可复现输入纳入版本管理，或明确决定本次跳过。Git 子模块及指向快照外的源码符号链接目前拒绝运行，而不是借用原工作区内容。

命令产生的未跟踪构建产物只留在快照里，整次进程退出被证实后删除。命令修改已提交源码或改动快照的 HEAD 时，即使退出码为 0 也不放行。非 Git 项目复制普通文件与目录，以内容指纹和起跑输入清单核对；原目录输入变化会使结果过期，测试修改原有输入不会为原目录放行，快照内新生成的构建产物不影响原输入身份。

复用依据为命令、源码提交和输入指纹；自动续验收、手动复用、批量预判与状态新鲜度共用这一判据。旧的仅有提交号的结果不再复用。真正的 Git 合并读取被测提交号，而不是再次解析可变的任务分支；分支不再指向该提交时拒绝合并。目标分支前进后的非 fast-forward 合并仍只记录被测范围，不宣称测过最终合并结果。

## 进程能力与恢复

门禁命令只有在启动器已加入可核对的内核进程集合后才获得执行许可。正常结束、取消、超时和恢复都以整次运行的退出证据释放工作区，不以原 PID 或进程组消失代替证据。

- Windows 使用门禁专属的独立 Job supervisor，在实际打开的进程句柄上核对创建时间，再用同一句柄加入 Job，持久化带代际的归属与集合为空的终结凭据。服务进程退出后仍可以恢复查询；Job 名字不存在但没有终结凭据时不放行。
- Linux 使用可写的 cgroup v2；无法建立或恢复集合时拒绝授权或保留停止责任。
- macOS 没有此实现所需的等价内核集合，因此目前拒绝执行门禁命令，日志明确说明原因。项目没有配置门禁的验收，以及用户明确选择本次跳过的路径不受影响。这是安全性优先的能力降级，不代表 macOS 已验证了 detached 后代退出。

缺失归属记录的旧运行可能继续阻挡合并与清理；单个根进程已退出不再自动核销这类责任。取消时若终态写入失败，响应为 `settlement_failed`，界面提示重试；运行占用与未结算状态继续保留，避免显示“已经结束”。

## 跨机接力

导出与移回携带冻结的验收方式、凭据运行 ID 和已结束的门禁历史；日志通过普通运行产物搬运。PID、内核集合、启动控制文件、测试快照和自动续验收选项不跨机携带，仍有停止责任的运行阻止接力。

导入将运行记录和日志地址映射为本机路径；移回时事务性替换历史，重复同一次传输保持幂等。迁入记录只证明历史，不直接作为当前机器重跑或复用的凭据。日志超限未携带或已被清理时，界面明确显示“当前不可查”，日志接口也不把缺失冒充为空日志。

## 回归入口

- `npm -w server run test:accept-merge`：合并、门禁编排、源码身份与生产进程能力测试。
- `npm -w server run test:handoff-accepted-return`：已验收任务移回、门禁凭据与日志双向接力。
- `npm -w web run test:accept-gate-dom`：真实无头浏览器中的取消失败反馈和日志缺失提示。

POSIX 上的编排回归使用仅存在于测试启动器中的进程组夹具，不代表生产围栏可用；生产进程、detached 后代和跨控制进程恢复用例独立运行，不加载该夹具。
