# 聊天模式

聊天入口位于工作区侧栏，以及新建面板的「单任务 / 团队 / 讨论 / 聊天」第四项。
群聊是项目下独立的持久会话，不参与一次性任务的完成、验收或队列结算；从聊天委派出来的工作仍是标准 ash 单任务。

## 本轮实现

- 群聊可创建、切换和配置成员，所有已注册的智能体类型均可参与，不限 Claude。每位成员使用现有的「智能体 · 模型 · 智能水平」选择器，保存具体执行器配置；CLI 安装、登录与供应商配置沿用 ash 原有要求。
- 用户消息里的明确 `@成员名` 触发回复。无点名的消息只保存；智能体回复中的点名不触发其他成员。代码块、行内代码和 Markdown 引用里的点名不触发。
- 被点名的成员获得该群近期历史；未被点名时不运行、不接收新消息。一次可点名多位成员，同群同成员的回复串行，全实例同时最多四个聊天回合。
- 咨询返回简短答复；明确的执行委派由被点名的智能体返回结构化任务描述，服务器创建并启动 ash 单任务。聊天回复最多 300 字；任务详情和完整执行日志位于任务页。
- 任务卡通过 SSE 更新运行状态、验证阶段和待答问题。任务完成时卡片显示结果就绪，不额外唤醒群成员。复杂任务默认采用独立 worktree；非 Git 项目按已有逻辑使用原目录。
- 停止回复会同时停止当前群正在运行与排队的聊天回合，结果持久化。已经创建的任务不受「停止回复」影响，可以打开任务页管理。
- 消息编号防止重复发送导致重复唤醒；服务重启后未完成聊天回合显示中断，不自动重新执行。再次点名可发起新回合。
- 界面包含频道导航、点名补全、成员状态、简短消息和任务卡；消息入场、点名菜单、任务状态及按钮有动效，并尊重系统减少动态效果设置。390px 宽度下聊天独占主工作区。
- 从任务新建面板切到聊天再切回任务时保留正文和已上传附件，不把任务草稿自动发送到群里。

## 范围与取舍

第一版是「当前用户 + 多个智能体」的群聊。多人实例中，群聊同时受创建者归属和项目可见性限制，不是多人类账号共享频道。

消息保存在 `chat_rooms` / `chat_messages` 表。页面展示最近 500 条，历史仍保留在数据库；智能体上下文最多携带近期 48,000 字符，不自动调用其他模型做摘要，也不读取其他群。界面明确提示长历史可能截断。

咨询还是执行委派由被点名的智能体解释，不使用关键词规则替代语义判断。聊天通过原有 `resolveExecutorFor` 和 `executor.run` 调用选定 CLI，保留模型、智能水平、profile 参数及供应商/登录方式，不换成另一个模型 API，也不再提供 Claude 专属聊天通道。

被点名后，工作目录为当前群所属项目，允许读取文件、查询资料辅助回答；没有配置项目目录时才使用临时目录，结束时只清理临时目录，不删除项目。实际启动前重新校验项目访问权与执行器归属，不携带任务回合凭证，不恢复其他聊天的会话。已识别的只读工具事件不会令正常回复失败；群里展示最终简短答复，或持久的边界警告，不展示查询过程。

聊天提示明确区分读取/查询和执行修改：咨询不修改文件、安装依赖或提交代码；明确的执行请求返回结构化 task，由服务器创建真实任务。第三轮修复增加系统检测与失败结算，不再仅依赖提示词；它不是 OS 只读沙箱，不能保证 CLI 在首次报告之前没有产生副作用。

当前实现没有附件消息、消息编辑、线程回复、全文历史检索或群聊归档。消息正文按纯文本显示，任务卡跳转到现有任务详情。

## 用户澄清与第二轮审查修复

第二轮审查指出 Claude-only 不符合「所有智能体」的原需求。随后向用户确认具体场景：「你问 @Codex 登录页怎么改比较好时，允许它先查看项目文件，再给简短建议吗？真正修改代码仍等明确交代，再创建任务执行。」用户答复：「当然允许啊，要不然智能体咋干活啊」。

因此本轮恢复所有智能体与原 CLI 的工具能力，取消此前误加的「聊天回合禁用一切工具」前提；没有把这一答复解释为咨询可以擅自修改代码。中文点名、权限隔离、任务卡、停止持久化及临时截图输出的修复继续保留。

## 第三轮修复：检测与持久警告

- 工具流只放行明确的读取/搜索工具，以及保守识别的单条读取命令；写入工具、未知工具、安装/提交/脚本、带重定向或复合语法的命令会终止回复。工具参数不原样写进群聊警告，以免泄露凭证。
- 起跑前建立项目目录元数据基线并启动递归监测，收尾时在进程清理后再次比对。即使 CLI 没发工具事件，在监测范围内新建文件、修改已有文件、删除或重命名也不能伴随 `task:null` 被当作正常成功。监测到变动时会结束剩余调用，不等模型宣称完成。
- 边界错误以 failed 状态及具体相对路径/工具名写进群聊消息；刷新、服务恢复或恰好点击停止都不会清掉这条警告。不把未经授权的副作用自动包装成任务，也不自动回滚用户文件；用户可检查变更，再决定是否明确委派后续任务。
- 该方案是检测后中止与诚实报告，不是事前沙箱。CLI 可能执行完才发事件，不能宣称已阻止首次写入。并发编辑也可能触发警告，文案不把变更来源擅自归因于智能体。扫描不跟随目录内符号链接，不保证发现项目目录外且未上报的操作；ash 数据库及其附属文件、RUNS_DIR 排除在监测外，以免自身消息持久化误触发。监测无法启动、核对失败或监测范围内超过 20 万条目时不会按正常咨询放行。

## 第四轮修复：大工作区可用性

- 基线与收尾扫描提前剪枝任意层级的 `node_modules`、`.worktrees` 和 `.claude/worktrees`，不枚举这些依赖和其他工作树，也不把它们的体量计入 20 万条目保护上限；其并发变更不再中止当前群咨询。未放宽工具事件检查，当前项目的源码、未跟踪文件及名称相似的普通目录仍被监测。
- 排除路径相对当前群的项目根目录计算。因此直接以某个 `.worktrees/<任务>` 为项目时，该工作树自己的源码仍受监测，不会因为上级目录名被整体跳过。
- 取舍是这些排除目录中未上报工具事件的改动不由文件监测兜底；这与已有项目外/符号链接/运行期目录的限制一样，不代表事前只读隔离。
- `npm -w server run test:chat` 新增大工作区回归：断言依赖与其他工作树完全不被枚举、不因并发变更误报，源码及相似目录名仍告警，当前工作树根目录仍受保护。
- `npx tsx server/scripts/test-chat-large-workspace.ts /Users/fjh/code/harness` 在报告中的真实主仓通过：假执行器走真实 resolver/run 路径读取 `package.json`，`runCalled:true`、`task:null`，约 237 ms。数据库连接固定在临时测试库；监测时对齐主实例的 DB/RUNS 排除路径，避免把在线服务持久化当作咨询副作用，未修改主仓或主数据库。
- 本轮仅调整后端监测范围。聊天回归、服务端构建、前端类型检查、多用户回归通过；首次完整构建的既有 `test:context-compact-quick` 浏览器测试等待控件超时，未改该功能，原样单独重跑通过。随后 `npm run build` 全量重跑和 `npm -w web run test:chat` 均通过，保留原有大 chunk 提示。
- 首次构建自动触发了独立无头 DOM 回归，未提前识别出该浏览器步骤；后续重试前已尝试扩展具名后台会话「🔎 大仓聊天回归」，仍返回 `Capability is not available: visibility`，无法满足保持后台的要求，后续验证使用临时 profile 的独立无头 Chrome。未激活、接管或直连用户普通标签，也未启动有头浏览器。

## 验证记录

- `npm -w server run test:chat`：所有 15 类智能体的创建/更新成员、点名派发；使用模拟执行器工厂验证真实 resolver/run 链路保留类型、模型和参数、只读工具事件不打断回复、项目目录不被清理、撤权和已停止调用不启动进程。新增真实 invokeChat/ChatService 链路的无工具事件写入复现，覆盖同步写入、流式写入、已有文件修改/删除/重命名、临时创建后删除、非只读工具、警告持久化及停止竞态；不冒充 15 个真实 CLI 全部实测。
- `npm -w web run test:chat`：独立数据库和模拟执行器，真实页面与 HTTP/SSE 链路覆盖 Codex/Claude/Grok 三种成员类型、中文相邻点名、咨询、原 Codex 类型的任务卡 running→done、停止刷新、390px 窄屏、减少动态效果、群间隔离和草稿保留。新增实际模拟写文件→调用失败→群中出现路径和警告→刷新后仍在、未误建任务的浏览器验证，截图为 `chat-boundary.png`。截图写入每次独立的系统临时目录，路径由控制台打印，不覆盖已跟踪示例图。
- `ASH_CHAT_SMOKE=1 npx tsx server/scripts/test-chat-cli.ts codex`、`... claude` 和 `... grok`：三个真实 CLI 读取临时项目文件中的随机标记（标记不在 prompt 中），回复准确且简短、task 为 null、源文件不变，均通过；验证的是读取咨询，不冒充真实代码任务验收。
- `npm run build`：全工作区构建及前端构建前置回归。
- `npm -w server run test:multi-user`、`test:claude-stream` 和 `test:claude-relay-settings-live` 均通过；原有多用户权限、CLI 输出解析和供应商配置行为保持正常。构建保留已有大 chunk 提示。

第三轮浏览器先尝试 Chrome 扩展具名会话「🔎 聊天副作用验证」。扩展拒绝 `visible:false`，返回 `Capability is not available: visibility`；无法保证新标签保持后台，因此改用临时 profile 的独立无头 Chrome，没有激活、接管或直连用户普通标签，也未启动有头浏览器。
