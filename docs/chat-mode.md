# 聊天模式

聊天入口位于工作区侧栏，以及新建面板的「单任务 / 团队 / 讨论 / 聊天」第四项。
群聊是项目下独立的持久会话，不参与一次性任务的完成、验收或队列结算；从聊天委派出来的工作仍是标准 ash 单任务。

## 本轮实现

- 群聊可创建、切换和配置成员，所有已注册的智能体类型均可参与，不限 Claude。每位成员使用现有的「智能体 · 模型 · 智能水平」选择器，保存具体执行器配置；CLI 安装、登录与供应商配置沿用 ash 原有要求。
- 用户消息里的明确 `@成员名` 触发回复。无点名的消息只保存；智能体回复中的点名不触发其他成员。代码块、行内代码和 Markdown 引用里的点名不触发。
- 被点名的成员获得该群近期历史；未被点名时不运行、不接收新消息。一次可点名多位成员，同群同成员的回复串行，全实例同时最多四个聊天回合。
- 咨询返回简短答复；明确的执行委派由被点名的智能体返回结构化任务描述，服务器创建并启动 ash 单任务。聊天回复最多 300 字；任务详情和完整执行日志位于任务页。
- 任务卡通过 SSE 更新运行状态、验证阶段和待答问题。任务完成时卡片显示结果就绪，不额外唤醒群成员。复杂任务默认采用独立 worktree；非 Git 项目按已有逻辑使用原目录。
- 停止回复会同时停止当前群正在运行与排队的聊天回合，结果持久化。已经创建的任务不受「停止回复」影响，可以打开任务页管理。
- 消息编号防止重复发送导致重复唤醒；服务重启后未完成聊天回合显示中断，不自动重新执行。再次点名可发起新回合。
- 界面包含频道导航、点名补全、成员状态、简短消息和任务卡；消息入场、点名菜单、任务状态及按钮有动效，并尊重系统减少动态效果设置。390px 宽度下聊天独占主工作区。
- 从任务新建面板切到聊天再切回任务时保留正文和已上传附件，不把任务草稿自动发送到群里。

## 范围与取舍

第一版是「当前用户 + 多个智能体」的群聊。多人实例中，群聊同时受创建者归属和项目可见性限制，不是多人类账号共享频道。

消息保存在 `chat_rooms` / `chat_messages` 表。页面展示最近 500 条，历史仍保留在数据库；智能体上下文最多携带近期 48,000 字符，不自动调用其他模型做摘要，也不读取其他群。界面明确提示长历史可能截断。

咨询还是执行委派由被点名的智能体解释，不使用关键词规则替代语义判断。聊天通过原有 `resolveExecutorFor` 和 `executor.run` 调用选定 CLI，保留模型、智能水平、profile 参数及供应商/登录方式，不换成另一个模型 API，也不再提供 Claude 专属聊天通道。

被点名后，工作目录为当前群所属项目，允许读取文件、查询资料辅助回答；没有配置项目目录时才使用临时目录，结束时只清理临时目录，不删除项目。实际启动前重新校验项目访问权与执行器归属，不携带任务回合凭证，不恢复其他聊天的会话。读取工具事件不会令正常回复失败；群里只展示最终简短答复，不展示查询过程。

聊天提示明确区分读取/查询和执行修改：咨询不修改文件、安装依赖或提交代码；明确的执行请求返回结构化 task，由服务器创建真实任务。这是基于用户指令的执行行为约束，不是 OS 只读沙箱，也不声称完整 CLI 在技术上无法写文件。

当前实现没有附件消息、消息编辑、线程回复、全文历史检索或群聊归档。消息正文按纯文本显示，任务卡跳转到现有任务详情。

## 用户澄清与第二轮审查修复

第二轮审查指出 Claude-only 不符合「所有智能体」的原需求。随后向用户确认具体场景：「你问 @Codex 登录页怎么改比较好时，允许它先查看项目文件，再给简短建议吗？真正修改代码仍等明确交代，再创建任务执行。」用户答复：「当然允许啊，要不然智能体咋干活啊」。

因此本轮恢复所有智能体与原 CLI 的工具能力，取消此前误加的「聊天回合禁用一切工具」前提；没有把这一答复解释为咨询可以擅自修改代码。中文点名、权限隔离、任务卡、停止持久化及临时截图输出的修复继续保留。

## 验证记录

- `npm -w server run test:chat`：所有 15 类智能体的创建/更新成员、点名派发；使用模拟执行器工厂验证真实 resolver/run 链路保留类型、模型和参数、工具事件不打断回复、项目目录不被清理、撤权和已停止调用不启动进程。保留点名解析、静默、禁止转发、历史隔离、幂等、任务关联、同成员串行、停止、异常输出及多用户权限回归。不冒充 15 个真实 CLI 全部实测。
- `npm -w web run test:chat`：独立数据库和模拟执行器，真实页面与 HTTP/SSE 链路覆盖 Codex/Claude/Grok 三种真实成员类型、中文相邻点名、咨询、原 Codex 类型的任务卡 running→done、停止刷新、390px 窄屏、减少动态效果、群间隔离和草稿保留。截图写入每次独立的系统临时目录，路径由控制台打印，不覆盖已跟踪示例图。
- `ASH_CHAT_SMOKE=1 npx tsx server/scripts/test-chat-cli.ts codex`、`... claude` 和 `... grok`：三个真实 CLI 读取临时项目文件中的随机标记（标记不在 prompt 中），回复准确且简短、task 为 null、源文件不变，均通过；验证的是读取咨询，不冒充真实代码任务验收。
- `npm run build`：全工作区构建及前端构建前置回归。
- `npm -w server run test:multi-user`、`test:claude-stream` 和 `test:claude-relay-settings-live` 均通过；原有多用户权限、CLI 输出解析和供应商配置行为保持正常。构建保留已有大 chunk 提示。

浏览器先尝试 Chrome 扩展具名会话「💬 全智能体聊天验证」。扩展拒绝 `visible:false`，返回 `Capability is not available: visibility`；无法保证新标签保持后台，因此改用临时 profile 的独立无头 Chrome，没有激活、接管或直连用户普通标签，也未启动有头浏览器。
