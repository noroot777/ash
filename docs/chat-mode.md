# 聊天模式

聊天入口位于工作区侧栏，以及新建面板的「单任务 / 团队 / 讨论 / 聊天」第四项。
群聊是项目下独立的持久会话，不参与一次性任务的完成、验收或队列结算；从聊天委派出来的工作仍是标准 ash 单任务。

## 本轮实现

- 群聊可创建、切换和配置成员，每位成员使用现有的「智能体 · 模型 · 智能水平」选择器，保存具体执行器配置。
- 用户消息里的明确 `@成员名` 触发回复。无点名的消息只保存；智能体回复中的点名不触发其他成员。代码块、行内代码和 Markdown 引用里的点名不触发。
- 被点名的成员获得该群近期历史；未被点名时不运行、不接收新消息。一次可点名多位成员，同群同成员的回复串行，全实例同时最多四个聊天回合。
- 咨询返回简短答复；明确的执行委派由被点名的智能体返回结构化任务描述，服务器创建并启动 ash 单任务。聊天回复最多 300 字；任务详情和完整执行日志位于任务页。
- 任务卡通过 SSE 更新运行状态、验证阶段和待答问题。任务完成时卡片显示结果就绪，不额外唤醒群成员。复杂任务默认采用独立 worktree；非 Git 项目按已有逻辑使用原目录。
- 停止回复会同时停止当前群正在运行与排队的聊天回合，结果持久化。已经创建的任务不受「停止回复」影响，可以打开任务页管理。
- 消息编号防止重复发送导致重复唤醒；服务重启后未完成聊天回合显示中断，不自动重新执行。再次点名可发起新回合。
- 界面包含频道导航、点名补全、成员状态、简短消息和任务卡；消息入场、点名菜单、任务状态及按钮有动效，并尊重系统减少动态效果设置。390px 宽度下聊天独占主工作区。
- 从任务新建面板切到聊天再切回任务时保留正文和已上传附件，不把任务草稿自动发送到群里。

## 范围与取舍

第一版是「当前用户 + 多个智能体」的群聊。多人实例中，群聊同时受创建者归属和项目可见性限制，不是多人类账号共享频道。

消息保存在 `chat_rooms` / `chat_messages` 表。页面展示最近 500 条，历史仍保留在数据库；智能体上下文最多携带近期 48,000 字符，不自动调用其他模型做摘要，也不读取其他群。界面明确提示长历史可能截断。

咨询还是执行委派由被点名的智能体解释，不使用关键词规则替代语义判断。即时聊天目前仅开放 Claude 的专用无工具通道，其他 CLI 在 API、成员候选和实际调用处被拒绝；已有不支持的成员需要重新配置。聊天仍沿用执行器的模型、智能水平及供应商鉴权，但不采用 profile 或单次调用的任意 extraArgs，委派后的正式任务不受此限制。

专用通道在进程启动时使用 `--tools ""`、空 MCP 配置和 `--strict-mcp-config`，并通过 safe mode、空 setting sources、禁用 hooks/自定义命令关闭自定义扩展；不带跳过权限或恢复会话参数。旧 CLI 若不识别参数，会报错而不是回退到完整执行器。临时工作目录与任务凭证清除继续保留；输出流上的工具事件检查只是额外防御，不再承担权限门控。这不是 OS 沙箱，仍信任本机安装的 CLI 本身。依赖用户 settings 中注入凭证的配置不会被加载，可使用挂载供应商的执行器；不恢复整份用户设置来绕过鉴权错误。

当前实现没有附件消息、消息编辑、线程回复、全文历史检索或群聊归档。消息正文按纯文本显示，任务卡跳转到现有任务详情。
