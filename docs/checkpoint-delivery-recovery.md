# 未送达续跑交代的持久恢复

本次只处理独立转出的 F1-A / F1-B：补偿途中继续运行，以及取消结果后进程退出。
原合批任务的其它结论和 N1 的送达确认故障不在此次改动范围内。

## 持久归属与恢复

续跑交代的文字、来源和占用代次，仍沿用任务行与 `scheduled_messages` 账本之间的事务转手。
`pending-checkpoint-recovery.ts` 从数据库读取未送达凭证，不以进程内补偿 Map 是否存在判断归属。
恢复覆盖 `pending` 和 `canceled`；`sent` 保留原先的送达确认语义。

单条取消、批量取消和投递器内部取消，都会尝试归还交代。归还失败时取消仍然有效，
原文继续留在 canceled 行；启动回收与后续扫描都能再次找到它。即使所有结果都已取消、
没有任何 pending 消息，扫描仍能恢复任务行并广播更新。

恢复沿用代次 CAS，回填和清账在同一原子批次中完成。账本所有权比较包含文字、来源和代次，
因此旧闭包不能清掉同一消息后来接走的同文新代次。真人或 agent 明确写下的新交代仍能替换旧代次；
系统自动等待不会替换尚由账本持有的同代次交代。

## 启动交接

运行、重试、队列推进、分组恢复及接力续跑，共用启动前的持久恢复检查。
普通输入交接也经过同一检查。回填失败或交代仍有在途所有者时，不启动缺失交代的默认“继续”回合；
手动 run / retry / retry-turn / fire 返回带 `checkpoint: true` 的 409。

单任务和团队的底层续跑入口，还会在占位后复查持久账本。投递器只对本次实际持租的消息提供所有权，
其它入口不能借这一批正在交接的交代启动。队列与分组在恢复受阻时不留下新的 queued 占位；
定时触发受阻时不消费班次。

启动受理和实际开跑分开记账：共用交接层等待执行会话交给消费者后的启动回执，
不等待整轮执行结束。内层检查拒绝时，手动入口返回拒绝，一次性与 cron 班次都保留重试机会。
queued 占位带独立持久凭证，回滚在同一 UPDATE 中比较状态、占位凭证和方向世代；
停止或后一次启动改变占位后，旧回滚不再写入或广播。

串行队列在交接前把推进请求写入任务行，一秒退避和启动后的 tick 都从持久记录重放；
只有收到实际启动回执或出现停止、分组暂停、等待替换等撤销事实时才清账。
未完成启动就中断的 queued 占位回到请求前状态，继续由持久请求补办。
没有推进请求的主动 paused 任务不会被全局扫描启动。补推复核原任务和检查点代次，
不把未消费检查点的旁路回合所产生的方向变化视为撤销。

单任务停止也接纳 paused/backlog 上的有效推进请求：同一状态写入撤销请求并落 canceled，
已经占位但尚未 spawn 的回合收到停止冻结。重放占位同时比较持久请求身份，
旧请求的占位失败补偿仍只重读持久请求，不凭迟到的定时器重新创建推进责任。

接力导出在停止并占住回合后也恢复交代，再以同一数据库事务检查剩余账本并读取任务快照。
这样 canceled 行上的交代会先回到任务载荷；遇到并发转手则拒绝导出，而不是输出一份缺少交代的快照。

恢复后由手动运行接手交代时，`task-checkpoint-delivery.ts` 在同一个事务内腾空任务行并登记独立凭证。
这种凭证使用 `origin=checkpoint:resume`、`status=canceled` 和在途租约：它不是待发送结果，
不出现在 pending 托盘，也不会被扫描当成一条普通消息自动执行。实际交付后才记 sent；
未交付则释放租约并归还。原进程退出后，启动回收同样能够接手这份凭证，避免从消息账本恢复后
又在手动运行入口退回仅存于内存的交代。

并行分组恢复仍不自动唤起带主动检查点的 paused 任务：恢复隐藏交代后，这类任务保留 paused，
由结果唤醒、手动运行或所属串行队列交接。没有把“恢复分组”改成批量消费主动暂停指令。

## 检查与范围

新增 `npm -w server run test:monitor-checkpoint-recovery`，接入 `pretest:monitors` 和后端 `test:accept`。
用例包含真实 Hono 路由、本地 CLI stdin、精确数据库写故障、真实所有者子进程退出、
单条/批量/全部取消、单条与合批交接、取消后只剩检查点、手动接手再退出、
任务/团队入口屏障、队列/分组占位，以及同文新代次的旧恢复快照。

修复轮补入 once/cron 内层拒绝、真实停止路由与分组回滚交错、占位替换、取消结果后
队列/串行组自动补推、分组暂停和新检查点使旧请求失效的定向回归；
另含两个独立进程间重放、占位中断恢复、停止/暂停后重启不复活、旁路/原生压缩之后补推。
停止用例覆盖自然 paused/backlog、撤销写失败、停止期间重放、迟到占位/补偿和执行/旁路起跑前停止。
执行记录通过任务哨兵登记。
其余回归保留给验收阶段执行，不引用旧任务的通过记录。
实现检查采用 shared / server / mcp 构建、差异检查与代码行数检查。
没有浏览器操作、Windows 专有分支改动、合并、部署或验收。

N1 保留：原话实际交付后，sent 确认写入仍可能失败。此次没有更改投递确认机制，
也不据此承诺端到端恰好一次投递。
