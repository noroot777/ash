## 输入框优先与辅助按钮（当前版本）

按最新反馈将任务目标作为页面视觉中心，沿用项目的灰白底色、紫色强调色、字体与执行器组件。取消常驻的大块配置区和示例卡片，输入框上沿用轻量按钮承载任务模式、工作方式、工作目录、分组与标签和写作参考；下沿放附件、启动设置、执行器及创建按钮。

自由工作流仍由任务执行器运行；起手式仍使用原有预设选择与编排，只有一份编辑器。团队角色与讨论者按需展开，自动审查、讨论轮数和共识闸门收进交付设置。执行器生效摘要在对应配置浮层中可查。辅助浮层复用 `useDismissable`，支持点外部收起、嵌套 Esc 与焦点恢复，关闭时保留已挂载配置和输入状态。异常、上传进度和定时校验信息仍直接可见。

验证通过：`npm -w web run typecheck`、`test:composer-upload`、`test:composer-studio` 与完整 `npm -w web run build`。专项回归覆盖辅助浮层与子菜单、配置保留、双向模板切换、320/390/700/900 像素布局、隐藏定时面板后的提交门禁，以及工作目录、标签、起手式执行器和模型的创建参数。完整构建包含上传、讨论、快捷键等既有前置回归，仅有原有的大 bundle 提示。另检查了真实 React 组件的桌面、手机、起手式与团队浮层截图；截图只保存在忽略的 `output/`，不加入版本库。验证使用 API 替身，未向用户项目创建测试任务。

浏览器通道：具名后台扩展会话“✍️ 任务输入聚焦验证”返回 `Capability is not available: visibility`，无法满足后台标签要求，因此降级使用临时 profile 的独立无头 Chromium。未使用有头浏览器、未接管或激活用户普通标签；测试结束关闭独立浏览器与临时 Vite 服务。重建目录缺失依赖，通过工作目录内的忽略软链复用已安装依赖，没有改动锁文件。

已将获认可的 `new-task-studio.html` 视觉方案接入 `TaskComposerPanel`，仍由主工作区原有的新建入口展示。本轮没有替换正在运行的主实例，也没有合并任务分支。
