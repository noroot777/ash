# 新建任务：写作台方案

入口：[new-task-studio.html](./new-task-studio.html)。静态文件可直接打开，无外部字体、图片或服务依赖。本方案独立于双栏版、摘要条版，不修改正式 composer。

## 设计取舍

- 沿用 harness 的灰白画布、`#5e6ad2` 强调色、无衬线字体、紧凑控件和 7–13px 圆角。
- 一个主输入面承载正文、附件、执行安排和创建操作，不再把配置铺成独立侧栏。
- 三段执行安排同时呈现「谁来做 / 在哪里做 / 如何交付」，点击后原位展开；同一时间只展开一个设置区。
- 分组与标签放在独立折叠行，不干扰最常见的输入与创建路径。
- 示例按钮追加任务骨架，不覆盖已有正文；保存草稿保留正文与配置，不保存附件文件。
- 团队展示调度、执行、审查三类角色；讨论展示两位讨论者，并隐藏保留的附件。

## 原型边界

这是信息架构与交互原型，不连接任务 API。创建仅生成页内回执，不启动执行器、不上传附件、不触发审查或合并。

执行器候选仅演示 Claude / Codex；模型保留「跟随执行器」。起手式线路为示例。正式集成时对应现有 RunTargetPicker、执行器 profile、工作流配置与任务提交逻辑，而不是把本原型的数据当成真实配置。

## 验证（2026-09-07）

先尝试 Chrome 扩展具名后台标签；`createBrowserTab` 传入 `visible:false` 返回 `Capability is not available: visibility`。为保证不激活用户浏览器，降级到独立、临时 profile 的 headless Chromium。没有使用 CDP 直连用户 Chrome，也没有启动有头浏览器。

浏览器实测通过：

- 空白正文禁用按钮，空格正文不能通过快捷键提交。
- 模式切换保留正文；团队展示三个角色，修改角色同步摘要。
- 配置只展开一个区域，Esc 收起并恢复触发器焦点。
- 关闭 worktree 后禁用 base 分支，运行位置摘要同步。
- 讨论禁止新选附件，切回单任务仍保留已有附件，附件可移除。
- 工作流、启动方式与草稿恢复一致；示例按钮可追加正文。
- 演示创建生成可见回执，不发送 POST 请求。
- 900 / 700 / 390 / 320px 页面没有横向溢出；检查了 1440px 桌面、团队展开态和 390px 窄屏截图。
- 最终页面控制台为 0 errors / 0 warnings；`node --check docs/demos/new-task-studio.js` 通过。
