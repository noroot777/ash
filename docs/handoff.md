# 任务接力（Handoff）

把一台机器上的任务——连同 git 进度、CLI 会话历史和附件——迁移到另一台跑着 Ash 的机器上继续。典型场景：下班前把 MacBook 上还没跑完的任务接力到家里的台式机继续。

---

## 快速流程

1. **配目标机器**：设置 → 默认规则，添加另一台 Ash 的地址（如 `http://192.168.1.50:4317`）
2. **在目标机上批准来源**：目标机的 设置 → 默认规则 → 接力来源，把这台机器放行一次（首次配对，见下）
3. **开始接力**：打开任务 → 输入框上方 → 「接力到另一台机器」
4. **预检**：探测对端、**核对对端身份指纹**、匹配项目、盘点可迁移的内容
5. **确认并发送**：可选「到达后自动续跑」

接力完成后，本机任务被标记为「已接力」，服务端硬拦其在本机运行。

---

## 身份与配对

每台 Ash 启动时给自己生成一对 ed25519 密钥，公钥的 sha256 就是它的**身份指纹**（设置页显示前 20 位，形如 `3F2A-91BC-D04E-77A1-9C55`）。私钥存在数据库文件旁边的 `<db>.identity.json`，不进库、不随任何请求外传。

不用共享口令，是因为口令解决不了接力真正的风险 —— 接力推出去的是**整个 git bundle 加完整 CLI 会话历史**，而口令只能证明「来的人有资格进」，证明不了「我要发的这台还是不是原来那台」。地址是会漂的（DHCP 换租约、路由器重启、局域网里有人抢地址）。而且共享口令必须存进 `app_settings`，`GET /settings` 会把它整份吐回前端。

### 两个方向，各管各的

| | 出站（我发给谁） | 入站（谁能推给我） |
|---|---|---|
| 存哪 | 设置里每个目标机上的 `peerFp` | `handoff_peers` 表（设置页「接力来源」） |
| 怎么建立 | 第一次接力成功后自动记住对端指纹（TOFU） | 对方第一次来敲门就落进待批准列表，你点「批准」 |
| 拦什么 | 这个地址背后换了机器 → **打包之前**硬拒绝 | 没批准的机器读不到分支、推不进任务，连项目清单都拿不到 |
| 怎么撤 | 设置里点掉那枚指纹芯片 | 「拒绝」或「删除」那一行 |

### 每个请求都签名

`/handoff/refs` 和 `/handoff/import` 要求来源机器已获批准，且请求带 ed25519 签名：

- 签名覆盖 `方法 + 路径 + 时间戳 + nonce + body 的 sha256`。**body 哈希在里面**，所以中间人留着签名头把 manifest 换掉一样过不了
- 时间戳偏差超过 ±5 分钟拒绝（两台机器的表要大致对上）
- nonce 用过一次就作废，原样重放的请求会被拒
- 指纹由公钥现算，冒充一个已批准的指纹必须持有对应私钥

幂等收口重试不受影响：那是一次全新请求，自带新的时间戳和 nonce，幂等靠 manifest 里的 `transferId`，两套机制互不干扰。

### 升级期的兼容

对端是旧版 Ash（不报身份）时：本机**没记过**它的指纹就按「无从核对」放行，并在预检结果里如实说明；**记过**就一律拒绝 —— 一台报过身份的机器突然不报了，不是降级就是冒充。

目标机上的「接力进来要先批准」可以关掉，退回旧行为（任何连得上端口的机器都能推进来）。只在源机版本太老、没法签名时临时用。

## 迁移了什么

| 迁移项 | 说明 |
|---|---|
| **任务元数据** | 标题、正文、状态、标签、定时计划——tasks/sessions 行按列原样带走 |
| **git 状态** | 任务分支上的提交打成 `git bundle` 带走；未提交改动会先做一个 WIP 提交 |
| **CLI 会话文件** | claude 的 `.jsonl`、codex 的 rollout——放到对端对应位置后 `--resume` 接着聊 |
| **会话产物** | `data/runs/<taskId>/` 下的 `.md`、`.trace`——否则对端任务历史是空白 |
| **上传附件** | 任务正文里引用的图片等文件，路径会自动改写成对端的本地路径 |
| **待发消息** | 尚未投递的定时消息 |
| **定时计划** | cron / 一次性触发计划，迁移后由对端触发 |

## 对端需要准备什么

1. **相同的 git 仓库**：对端必须有同一个仓库的克隆（不要求完全同步——接力会协商增量传输）
2. **已建好项目**：在对端 Ash 里新建项目，指向那个仓库的绝对路径
3. **已安装对应的 agent CLI**：如果任务用的是 claude，对端也得装好并登录过 claude

> **对端的 git 不需要提前同步到最新。** 接力时会用 `git bundle` 做增量传输——先协商对端已有哪些提交，只打包缺少的部分。甚至对端是一个全新的浅克隆也可以工作，只是 bundle 会大一些。

## Worktree 处理

### 源机（导出侧）

1. 检查任务是否在独立 worktree 中运行。不在的话代码不随任务迁移，对端以自己仓库的当前状态为准
2. 检测未提交改动（`git status --porcelain`），有的话在任务分支上做一个 WIP 提交
3. 向对端查询分支尖（`GET /handoff/projects/:id/refs`），确定哪些提交对端已有
4. 打包：
   - **对端全都有**（分支完全同步）→ 空 bundle，零传输
   - **对端有部分**（增量）→ `git bundle create --not <已有提交>` → 只传缺少的
   - **对端什么都没有**（全新克隆）→ 全量 bundle，整条历史
5. bundle 大小上限 300 MB

### 对端（导入侧）

1. 收到 bundle 后 `git bundle verify` 确认 prerequisite 提交存在
2. `git fetch` 把分支拉入仓库
3. `prepareWorktree` 恢复任务的工作目录
4. 如果对端项目不是 git 仓库，退化为共享目录运行，如实记录 notes

### 分支名不一致的情况

源机的任务分支名可能已被手动改过。导入后 Ash 仍按标准规则（`ash/<taskId>`）建 worktree，导入的提交留在源分支上。界面会提示「分支名不一致，必要时手动合一下」。

## 会话续接

CLI 会话文件是续接对话历史的关键：

- **claude**：`~/.claude/projects/<cwd-slug>/<sessionId>.jsonl`
- **codex**：`~/.codex/sessions/YYYY/MM/DD/rollout-*-<threadId>.jsonl`

**迁移成功**：对端续跑时在同一 CLI 会话里注入一段前言（「本任务从 X 接力到本机」），然后接着之前的对话。全价读史一次（和本地隔夜续跑同价）。

**迁移失败或不支持的执行器**：对端全新开一个 CLI 会话，任务正文会完整嵌入首条消息。git 进度仍在，只是对话历史断了。这是有意的干净退化——不会出现错误状态。

> 会话文件大小上限 100 MB。超限的会跳过并记 notes。

## 网络失败与幂等重试

接力使用 `transferId` 保证幂等：

| 场景 | 表现 |
|---|---|
| **正常完成** | 本机标记 `direction: "out"`，对端标记 `direction: "in"` |
| **网络断了** | 本机标记 `pending: true`（「接力未确认」），对端可能已收到也可能没收到 |
| **重试** | 打开接力对话框，看到「原样重发」提示。对端用 `transferId` 做幂等：已有就直接成功返回，不重复导入 |
| **换目标** | 必须先在横幅上移除接力标记，再接力到新目标 |

## 限制与不支持

- **团队模式和 Duet**：V1 不支持。只支持 single 模式的任务
- **队列中的任务**：不能接力。先从队列中移除，再接力
- **已归档的任务**：不能接力
- **传输仍是明文 HTTP**：身份校验解决的是「谁在跟我说话、内容有没有被改」，不解决**窃听**。接力推的是整个仓库和完整对话历史，所以仍然只在可信内网中使用（Ash 其它端点也依旧没有鉴权，终端 API 本身就是个 shell）
- **executorId 不迁移**：对端没有源机的执行器 profile，落库时按 agentType 走默认

---

## 在本机继续（逃生门）

接力出去的任务在本机被硬拦运行。如果需要在本机继续：

1. 任务详情页顶部横幅 → 「在本机继续」
2. 确认对话框提示风险：对端那份任务仍然存在，需要用户自行确保不会两边同时跑
3. 确认后清除接力标记，任务恢复为本机可运行

## 故障排查

| 症状 | 可能原因 |
|---|---|
| 预检时「探测对端失败」 | 对端 Ash 没启动、网络不通、地址填错。确认 `curl http://对端:4317/api/handoff/ping` 有响应 |
| 「目标机还没批准本机」 | 到目标机的 设置 → 默认规则 → 接力来源，找到本机指纹点「批准」。这次探测已经把本机送进它的待批准列表了 |
| 「目标机的身份和上次不一样」 | 那个地址背后换了机器。核对两边设置页上的指纹：确实是同一台（重装过/换了新机），就在设置里点掉记住的那枚指纹再接力；对不上就别发 |
| 「时间戳超出 ±5 分钟窗口」 | 两台机器系统时间差太多，对一下时间 |
| 「本机已有同 id 任务」(409) | 之前接力过一次或手动创建了同 id 任务。在对端删掉那个任务再重试 |
| 「会话 id 冲突」(409) | 曾从对端接力回来过。删掉对端的旧任务及其会话再试 |
| 接力成功但对端续跑时看不到代码进度 | worktree 没接上导入的分支（notes 里有说明）。手动 `git checkout <源分支>` 或 merge |
| 对端续跑时 agent 不知道之前做到哪了 | 会话文件没迁移成功。agent 会全新起跑并在首条消息里看到完整任务正文，不影响正确性 |
| bundle 太大（>300MB） | 仓库历史太重。先在源机 `git gc --aggressive`，或确保对端已有部分历史（`git fetch` 一下）来减少增量 |
