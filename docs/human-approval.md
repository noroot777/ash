# 回合占位的离机授权

`reclaim-turn` 会解除回合互斥，即使原持有者仍存活也可能生效。自用模式的默认本机身份、浏览器头和公开页面 nonce 都不构成人工身份凭据。这个入口现在验证独立 Ed25519 私钥的签名；没有有效公钥配置时返回 503，不释放占位。现有账号、项目可见性、agent 身份拒绝和可疑占位判据仍然生效。

## 信任边界

私钥的部署位置是另一台由用户控制、agent 无权访问的设备或隔离签名环境。ash 服务只持有公钥，没有申请签名、注册新密钥或替换授权公钥的 HTTP 接口。页面、授权申请和公钥都是公开资料；读取它们、伪造 Origin / Fetch 头、删掉 agent 身份头都不能生成签名。

这不是同 UID 任意代码执行的沙箱。同账号 shell 若能改写服务代码或数据、替换启动配置、调试服务进程、重启服务或读取签名私钥，仍能绕过服务自身的检查。要覆盖这个威胁，服务及其公钥配置归属于 agent 无法写入或调试的独立系统账号，agent 的工作区、进程和终端权限也与服务隔离；私钥不位于 agent 能读取的文件、环境变量、命令行、浏览器存储或远程 shell 中。本轮实现的是这条部署边界内的请求级授权，不宣称当前同账号、无限制 shell 的默认部署已获得进程隔离。

## 配置和操作

1. 在离机设备运行 `node scripts/human-approval.mjs generate approval-private.pem`。输出的是公开的 `ASH_HUMAN_APPROVAL_PUBLIC_KEY=...`；私钥只保存在该设备，重复生成不会覆盖已有文件。
2. 公钥没有默认文件位置，写到数据目录不会被自动信任。可把公钥加入可信的服务启动环境 `ASH_HUMAN_APPROVAL_PUBLIC_KEY`，或在启动环境显式指定 `ASH_HUMAN_APPROVAL_PUBLIC_KEY_FILE` 的绝对路径。后者的文件及全部上级目录不归服务运行账号所有、不可被它写入，且路径不含符号链接；例如管理员管理的 `/private/etc/ash/approval.pub`，而不是 agent 工作区、数据目录或服务账号自己的主目录。属主相同但 chmod 只读也会拒绝，因为该账号可以自行改回权限。无法核验独立文件属主的平台仅支持启动环境中的公钥。
3. 可信文件在申请与验签时热加载，无需重启，当前占位保持不变；路径需要事先在启动配置中指定，但公钥内容可由独立管理员在救援时补配。非空的 `ASH_HUMAN_APPROVAL_PUBLIC_KEY` 优先于文件；文件缺失、不可信、不可读、内容格式不对或算法不是 Ed25519 时入口保持关闭。加载、轮换、删除、权限变化及无效内容的状态变化会记录 warn 日志和公钥指纹，不记录公钥原文；重复的相同失败状态不逐请求刷日志。配置仍不是普通 settings 表中的可写选项。
4. 页面中点击“申请人工授权”，将文本框中的完整 JSON 保存为 `request.json`，转到离机设备。页面显示剩余有效时间；“查看当前申请”返回同一份未过期申请，不延长时限，也不清掉已贴入的签名。到期后按钮变回“申请人工授权”，可获取新的五分钟申请。
5. 离机运行 `node scripts/human-approval.mjs sign approval-private.pem request.json`。核对目标任务、占位代次、风险和到期时间，输入任务 ID 后才输出签名授权 JSON。
6. 将结果粘回页面，点击“确认风险并放开回合占位”。默认五分钟内有效；过期、重复使用、任务或占位变化、账号变化、服务重启后都不能重用。加载时发现更换、删除、不可信或无效公钥会使待处理申请失效，恢复旧公钥也不能恢复已失效申请。

服务签发的原始申请字节绑定协议版本、当前服务启动实例、授权公钥指纹、随机 challenge ID、动作、任务、账号、占位 seq / claimedAt、风险、签发和到期时间。离机工具校验有效期长度不超过五分钟，不再用本机时钟限制到期时刻的上界，因此慢两秒或一分钟不会误拒；字段不合法、公钥不匹配、已过期分别报错。最终到期判断仍由服务端完成。

申请通过 `POST /api/tasks/:id/reclaim-turn/approval` 创建，和放开接口共用账号、agent 和跨站检查；可见任务上的申请拒绝会写入持久历史。申请不落盘，按 `(账号, 动作, 任务)` 各保留一份：同一占位反复申请返回同一份未过期申请，避免匿名调用者挤占全局额度，或靠不断换新申请使用户手里的签名作废；占位变化后新申请替换旧申请，过期时清理。

验签和消费是同步操作，释放前再核对同一占位 seq，没有异步让出造成的换主窗口。释放后的任务历史记录授权公钥指纹，不把隐式本机身份或一次 HTTP 请求称为“用户本人”。

本轮只覆盖回合占位的人工放开入口，没有扩展至 CUA、接力、删除等其他危险动作，也没有改变原唤醒、补投和停止策略。
