# 页面批注(指指画画)方案与执行拆解

来源:讨论任务 GQ7rSor9YrNS 的正式产出(2026-09-10,双讨论者收敛稿)。本文件是执行规格——各执行者动工前先读完本文;需要更深的论证过程可读 `data/runs/GQ7rSor9YrNS/H7g-kgWblzw5.md`(讨论者 A)与 `data/runs/GQ7rSor9YrNS/dvVY7l0RDpPX.md`(讨论者 B)。

## 一、目标与难度定位

在 ash(harness)的任务界面里提供三层能力,对标并超出 Claude Design / Codex 的页面批注体验:

1. **批注闭环(首版)**:在智能体产出的 Web 页面上点选、圈画、留言 → 智能体改源码 → 回来复看确认。
2. **录制批注(增强档)**:边说边指,语音、鼠标指点、页面变化按统一时间轴对齐,生成可编辑的修改清单——解决「前端需求难以文字描述」的表达问题。
3. **动态过程捕捉(录制档内建)**:针对「点了按钮后某处异常跳动一下」这类瞬态 bug,按场景组合录屏与页面仪器,留下机器可读的证据链。

**总体难度:中等,可分步交付。** 依据:`server/src/preview-*.ts`(约 3400 行)已提供带 token 鉴权的预览反代;`preview-proxy-rewrite.ts:33` 已向被代理 HTML 注入运行时脚本,注入管道现成;`task-reply.ts` 支持文字与附件、排队与唤醒。所有新能力都落在「注入 runtime + 批次投递」两条管线上,不新造代理体系或模型调用链。

## 二、批注闭环(首版)

交互:预览工作区(iframe 内嵌代理预览,可行性已验证——代理丢弃上游 CSP/X-Frame-Options 并统一下发 sandbox 头)→ 浏览/标注双模式 → 点选(可向上选父容器)或矩形/画笔圈画 → 每条标注创建时即记录上下文 → 评论在父层填写,攒成稳定 ID 批次 → 发送前预览 → 进现有 reply 链路 → 修改期间预览按现有生命周期关闭(已验证 `status.ts:26`),等待区显示批注卡片与已存图像 → 回合释放且无待投递后续消息时提示重开 → 多特征重找元素逐条确认(selector 仅候选)→ 新意见成新批次。

实现分层:预览工作区(前端独立模块 ~500 行);注入标注脚本(与 `previewBrowserBridge` 并排,~600 行:默认休眠、MessageChannel 握手激活、closed shadow root + 捕获监听、元素卡片提取带脱敏);现场记录按**证据分用途**(意见/DOM 摘要/图像,图像逐张标来源);批次投递(幂等、留草稿、重启可恢复,UI 状态机按投递记录走);prompt 把页面上报内容框成数据、范围歧义走 `ask_question`。配套:meta CSP 中和(已验证缺口)、静态产物候选(框架识别优先)、异常页面「改用截图批注」一步可达降级。

## 三、录制批注(增强档)

### 采集矩阵:三类轨道,按录制意图组合

| 轨道 | 载体 | 职责 |
|---|---|---|
| 语音 | 父层 `getUserMedia` + MediaRecorder,server 端词级时间戳转写 | 用户在说什么 |
| 操作与元素上下文 | rrweb(DOM 快照 + 增量变更 + 鼠标滚动事件)承担,替代自写全量事件采集;外加动态仪器:`PerformanceObserver` layout-shift、点击后 rAF 位移采样、console 错误与网络时序 | 操作了谁、什么变了、为什么 |
| 画面 | `getDisplayMedia`(用户选定标签页)+ MediaRecorder,30–60fps | 用户实际看到的像素过程 |

**录制入口按意图给两种预设**(可手动改):

- **「说明修改」**(表达需求、指哪儿改哪儿):默认录音 + rrweb/仪器,**不开录屏**——零授权弹窗、零摩擦,这决定日常使用率;录屏可手动开。
- **「抓动态 bug」**(复现瞬态视觉问题):默认**加开录屏**。理由:rrweb 是 DOM 重建渲染,不能默认重放的每一帧等于用户当时看到的画面(Canvas、字体闪烁、纯合成层动画可能失真),而瞬态 bug 可能难以再次复现——第一次就要用像素抓住,事后「重录一次」的成本高于一次授权弹窗。

**明确的分工共识:录屏保存视觉过程,rrweb 保存操作与元素上下文,录音保存意图——三者互不替代。** rrweb 的额外收益:DOM 级回放(拖时间轴停在跳动瞬间直接圈元素)、体积约为视频的百分之一、关键帧可事后在 headless 浏览器(Playwright,合规)回放截取,标注「重建渲染」来源。

### 对齐与产出

统一时间基准(`performance.now()`);转写出现指示代词时按**不对称窗口**(人先操作后解释,向前回看数秒)查 rrweb 里附近时刻的鼠标目标与 pin 事件(**标记快捷键**打点,不占左键、不误触页面);多候选按停留时长 + 距离打分,低置信度标 ⚠ 进清单让用户点选。

录后管线:停止 → 转写 → 时间轴合并 → **可编辑修改清单**,例:

> 08.2s 点击「保存」→ 08.4s layout-shift(0.31):`.toolbar` y 620→588 后回弹,同期插入无尺寸 `<img>`;09.0s 用户指向工具栏说「这里刚才跳了一下」→ 整理为:「点击保存后底部工具栏短暂上跳」+ 元素信息 + 前后关键帧(+ 录屏片段)

确认后作为批次进入与批注相同的投递链路。**交给智能体**:复现步骤、结构化跳动记录、关键帧、元素位置变化、语音原文与整理后意见、console/网络线索;视频与 rrweb 录像作为存证附件,不直接喂模型(兼容所有执行器)。

限制与合规:首版限 1–3 分钟;显式起止控件;发送前可回放删改;录制产物走附件链路、不含预览凭证。`getDisplayMedia` 是用户主动授权共享自己的页面,不属自动化验证通道;开发验证按「扩展后台标签 → 无头」降级执行。

## 关键决策与理由

1. **主画布是真实预览,截图批注降为兜底**:标注层叠在 iframe 上,每笔同时锚定元素与坐标。
2. **证据分用途,放弃单一「现场权威记录」**:DOM 序列化硬边界已论证(输入值/Canvas/Shadow DOM/登录态不进序列化);意见、DOM 摘要、图像各司其职、逐张标来源。
3. **首版分轮迭代;热更复用后置且按能力判据**(工作区身份一致、服务类型已验证支持热更、依赖配置相容、探活正常),不按任务状态划分;`rerun-gate` 不绕。
4. **录屏与 rrweb 是分工不是二选一**:曾议「录屏为主」(单看视频难知对应元素、模型消化差)与「rrweb 为主」(重放不保证等于用户所见)各自被对方证伪为不完整;最终按轨道分工 + 按录制意图定默认组合。
5. **场景化默认**:说明修改 → 不开录屏(授权摩擦决定日常使用率);抓动态 bug → 默认开录屏(瞬态问题第一次就要用像素抓住,重录成本高于一次授权)。
6. **对齐是不对称时间窗查表**:pin 快捷键锚点 + 打分 + 清单确认,歧义不出门;不机械绑定说话瞬间。
7. **智能体不直接吃视频**;源码定位交给 CLI 智能体 grep(构建期插件控制不了任意项目、React 19 无 `_debugSource`),范围歧义走 `ask_question`。
8. **安全模型**:发送门槛在父层;opaque origin 下身份靠 MessageChannel/source(`event.origin === "null"` 不可作校验依据);页面上报一律当数据;持久化不存预览凭证。
9. **复用现有链路**:`replyToTask`、附件、注入管道、提问机制全部现成。

## 风险与待验证假设

1. **采集组合的实测数据缺失**:rrweb 对真实跳动类 bug 的重放保真度、录屏授权流失率、两者体积与材料质量——spike 先行,数据定默认。
2. **对齐准确率**:不对称窗参数、pin 使用率、打分规则需真人调参;whisper 类中文口语词级时间戳质量待测,是新外部依赖。
3. **仪器覆盖面与开销**:transform 动画类位移不计入 layout-shift(靠 rAF 采样与 rrweb 补);多仪器同开对低端机的性能影响需限流。
4. **注入 runtime 与任意页面共存**:meta CSP 中和后行为、`window.top` 自检、全屏 Canvas 退化——降级入口兜底。
5. **点选信息对源码定位的帮助率**:首版真实任务统计,不达标再考虑框架插件。
6. **复看重定位、竞态一致性**(重开竞态、串批次、重复入队)已列验证清单;跨平台启动改动需 Windows 真机验证;热更复用动手前读透 `rerun-gate.ts`/`preview-start-state.ts`。
7. rrweb 若引入,是新的第三方运行时依赖(注入体积、维护、与被预览页的兼容),需评估裁剪。

## 残留分歧(待用户拍板,不阻塞第 0 档与首版)

**一条:录制档事件层的实施顺序。** B 建议首版先做「录屏 + 录音 + 轻量自写鼠标/元素记录」(~0.5 人周),rrweb 引入后评估;A 建议事件层直接以 rrweb 落地(1–2 人周含回放器)。两条路径给智能体的首批材料相同,差异在交付节奏与返工风险,结合采集 spike 结果由用户拍板。双方已合意:无论哪条顺序,动态 bug 场景的真实录屏不被 rrweb 替代。
