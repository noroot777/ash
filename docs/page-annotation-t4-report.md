任务：LDUUAQLtPTUg。实现范围为 `docs/page-annotation-plan.md` 的 T4。

## 交付内容

- 修改期间保留独立等待区，逐条展示已发送意见、原目标摘要和已存图像，并明确标示「这不是可操作页面」。未存图像时展示原路径、目标特征及原位置摘要；没有还原旧页面或把它伪装成可操作页面。
- 等待期间可补评论，复制所选条目的原现场为新 ID 批次，文字标明来自原记录。原批次保持不变；新批次仍经过 T3 的保存、预览确认、幂等投递链路。
- 自动重开只给提示。用户点击后重新核对回合状态，再调用原有自由预览/工作流预览入口；没有自动启动预览的 effect。`status.ts`、`pending-messages.ts`、`rerun-gate.ts`、预览启动与结算代码未修改。
- 回合状态检查同时覆盖数据库任务状态、回合占位、运行态、rerun gate，以及所有 pending 后续消息（含投递租约、尚未到点的定时消息）。前端收到状态/后续消息事件即撤销旧提示，废弃在途旧响应；慢请求合并，避免轮询相互覆盖导致永远等不到结果。
- 关闭工作区、主动关闭/取消自由预览或点击「不再自动提示」后，按 taskId 保存关闭偏好。刷新后仍保留，可通过「恢复提示」主动恢复。
- 重开后逐条查找目标，结合文字、角色、标签、文档位置与 selector 候选评分。最低分 0.72，前两名差距至少 0.12；无文字泛容器、文字冲突、路径不同、多候选歧义均保守降级。高亮只读取新页面目标的实时边界，不发送或复用旧坐标作为新页面覆盖层。
- 每条有「满意 / 继续圈」。继续圈先记录复看选择，再开始新批次圈选。回合释放记录与用户确认分别持久化在独立表中，不改写已投递批次。释放时间为批注服务首次观测到可复看的时间，并保留当时任务状态；它不等于用户验收，也不把 failed/paused 视为完成。
- 标注面板的「此页面在内嵌预览中表现异常？改用截图批注」直接打开 T1 编辑器，复用其截图草稿、图片附件和 reply 链路。window.top 自检、全屏 Canvas 等页面沿此入口降级。

## 验收清单

| 条目 | 落实方式与验证 |
|---|---|
| 标注不触发页面行为 | 复用注入 runtime 的捕获拦截；重定位不点击或聚焦目标，复看保持标注模式。实际注入脚本的 DOM/MessagePort 模型测试验证定位和后续点击不触发页面 click。 |
| 滚动缩放后坐标一致 | 评分以文档位置和视口归一化；高亮每次绘制读取新元素边界。测试覆盖滚动偏移、2 倍缩放评分一致，以及滚动后高亮读取实时 y 值。 |
| 任务切换不串批次 | 工作区按 taskId 挂载，草稿/关闭偏好按任务隔离，恢复时核对本地草稿 taskId，服务端复看按 taskId+batchId+itemId 校验；旧状态响应及旧文档匹配响应作废。测试验证旧任务响应被丢弃、跨任务复看请求 404、关闭偏好不串任务。 |
| 网络重试不重复入队 | 新意见进入原 T3 稳定 ID 批次投递；原子队列写入和回执未改变。测试覆盖 12 个并发 HTTP 重试仍只有一条队列消息，以及新进程恢复后的重试。满意确认的重复 PUT 也不重复写入或刷新确认时间。 |
| 旧预览失效后记录仍可读 | 等待区读取持久批次及 uploads 图像，不依赖预览 token、iframe 或服务存活；无图展示摘要。静态渲染测试验证等待区没有 iframe，仍显示原意见、原附件及无图摘要；批次测试验证跨进程恢复原现场。 |
| 后续消息与自动重开的竞态 | pending 行包括正在投递的租约；回合占位覆盖 sent→running 的状态缝隙，rerun gate 覆盖收旧预览期间。测试逐段验证不能重开；前端允许 reviewable 回退为 modifying，事件使旧可重开响应失效，用户点击再检查。 |
