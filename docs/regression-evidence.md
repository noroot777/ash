# 回归执行记录与复用资格

回归登记保留执行者来源、原始命令、工作目录、完整日志摘要、真实退出码，以及数据库分配的 `generation`。时间戳仅用于展示；同命令、同目录的 `latest` 由登记代次确定，而不是完成时间。并发执行中，较早登记的命令即使较晚完成，也不覆盖较新记录。清单保留所有历史结果，包括失败、未完成与被后续执行取代的记录。

## 当前的保守降级

现有 runner 在可被其它协作者修改的工作目录执行任意 shell 命令。Git 树既不能证明命令执行期间没有发生内容切换，也不能覆盖忽略配置、依赖、构建产物、子模块脏文件及外部输入。因此当前登记的输入协议明确为 `mutable-workspace / unverified`，测试前后 Git 快照仅用于诊断。

当前清单协议为 2，输入策略为 `immutable-closed-inputs-required`。由于现有执行方式不具备不可变、闭合的实际输入证明，所有现有记录的 `reusable` 都是 `false`，包括 Git 树相等、退出码为零的记录。旧记录缺少输入证明时同样降级。`passed` 仍准确表示该次命令的实际结果，不表示它验证过当前版本。这次修复没有引入隔离 runner，也没有把调用方自报的输入范围当成完整输入闭包。

## 清单生命周期

自由审查、就地验证与历史独立审查在首次进入、续跑、上报结论及实际结算时重新生成清单。异常重试先生成完整审查协议，再发送缩略续跑消息。旧清单的复用授权在重新核验时撤销；如果上报通过或消费通过结论时发现旧授权，结论入口拒收，或者结算降为未通过。

证据 JSON 不是授权来源：原始字段以数据库为准，日志摘要独立校验；读取旧 JSON 只用于撤销可能遗留的授权，不会授予新资格。

旧表迁移在数据库写事务中按原始插入顺序补齐代次，保留已有字段，输入证明保持空值。新登记使用 SQLite `AUTOINCREMENT`，删除历史和进程重启不会让已分配的代次回退。

相关回归：`npm -w server run test:regression-evidence`，涵盖执行期间 ABA 内容切换、忽略输入与子模块、同毫秒与墙钟回拨、并发完成倒序、迁移重启，以及所有审查消费入口。
