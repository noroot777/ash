# 回归执行记录与复用资格

回归登记保留执行者来源、原始命令、工作目录、完整日志摘要、真实退出码，以及数据库分配的 `generation`。时间戳仅用于展示；同命令、同目录的 `latest` 由登记代次确定，而不是完成时间。并发执行中，较早登记的命令即使较晚完成，也不覆盖较新记录。清单保留所有历史结果，包括失败、未完成与被后续执行取代的记录。

## 当前的保守降级

现有 runner 在可被其它协作者修改的工作目录执行任意 shell 命令。Git 树既不能证明命令执行期间没有发生内容切换，也不能覆盖忽略配置、依赖、构建产物、子模块脏文件及外部输入。因此当前登记的输入协议明确为 `mutable-workspace / unverified`，测试前后 Git 快照仅用于诊断。

当前清单协议为 2，输入策略为 `immutable-closed-inputs-required`。由于现有执行方式不具备不可变、闭合的实际输入证明，所有现有记录的 `reusable` 都是 `false`，包括 Git 树相等、退出码为零的记录。旧记录缺少输入证明时同样降级。`passed` 仍准确表示该次命令的实际结果，不表示它验证过当前版本。这次修复没有引入隔离 runner，也没有把调用方自报的输入范围当成完整输入闭包。

## 清单生命周期

自由审查、就地验证与历史独立审查在首次进入、续跑时生成诊断清单。异常重试先生成完整审查协议，再发送缩略续跑消息。结论上报与结算只核验本轮持久化的依据，不再重新生成、扫描全部历史执行日志。合并结果审查没有任务分支复用资格，也不写空清单。

`regression_evidence` 按服务端确定的轮次目录保存证据代次、撤销事实、该代次之前的执行 id、已接收的独立依据以及材料不可用的实际原因。撤销只增不减，清单刷新、删除、改写、请求重试、MCP 补录及服务重启都不能将同一份无依据结论升级成有效结论。旧轮次首次接入且存在执行者历史记录时，因无法证明其旧结论未引用历史结果，同样保守拒收无依据的通过结论。

恢复通过使用 `report_stage.verificationBasis={kind:"independent",generation,monitorIds}`：`generation` 来自本轮提示、清单的 `verification` 展示字段或拒收响应；检查由本轮 `start_monitor` 真实执行、完整正常退出且退出码为零，没有提前停止条件。服务端校验本轮归属、排除该代次之前的执行，并持久保存执行身份和完整日志摘要。上报与补录携带相同依据，结算再校验已接受的依据；仅重读清单、重复上报、更新报告不构成新执行。此凭据只说明本轮实际做过哪些独立检查，不授予执行者记录跨版本复用资格，也不替代审查者选择完整验证范围。

诊断清单 I/O 故障与旧引用撤销分开记录，不否定不依赖它的独立验证。独立执行依据本身暂不可读时，上报保留实际错误并返回可重试的 503。结算在读取材料前持久保存本轮真实退出结果与待恢复状态；已观察到的失败不会因后续重试变为成功。异常结束的审查不依赖证据读取即可收尾，独立测试通过并不代表审查回合正常结束。

正常退出但依据暂不可读的审查保留原结论、依据与轮次，不虚构测试失败。恢复可读后，自由审查、就地验证和历史独立审查的启动期对账使用已保存的退出事实重新核验；没有退出记录的遗留轮次不会仅凭任务终态或已有结论推定成功。轮次展示也使用该事实，不再以原任务的终态替代审查结果。

HTTP 上报及 MCP 补录使用同一事务入口保存结论与独立依据；提交时重验轮次、证据 generation、回合和方向身份。任一写入失败，两项一起回滚，事件与时间线只在事务提交后发布。进入结算后，相同结论与依据可幂等重试，不能改换结论或依据。

用户显式重开异常结束的自由审查时，同一事务清空该次结论并轮换证据 generation；旧退出结果与旧依据不带入新尝试，既有撤销事实保留，先前执行进入排除列表。普通自动恢复不会做这一重置。

证据 JSON 不是授权来源：原始字段以数据库为准，日志摘要独立校验；读取旧 JSON 只用于撤销可能遗留的授权，不会授予新资格。

旧表迁移在数据库写事务中按原始插入顺序补齐代次，保留已有字段，输入证明保持空值。新登记使用 SQLite `AUTOINCREMENT`，删除历史和进程重启不会让已分配的代次回退。

相关回归：`npm -w server run test:regression-evidence`，涵盖执行期间 ABA 内容切换、忽略输入与子模块、同毫秒与墙钟回拨、并发完成倒序、迁移重启，以及所有审查消费入口。
