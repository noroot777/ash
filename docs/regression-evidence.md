# 回归执行记录与复用资格

回归登记保留执行者来源、原始命令、工作目录、完整日志摘要、真实退出码，以及数据库分配的 `generation`。时间戳仅用于展示；同命令、同目录的 `latest` 由登记代次确定，而不是完成时间。并发执行中，较早登记的命令即使较晚完成，也不覆盖较新记录。清单保留所有历史结果，包括失败、未完成与被后续执行取代的记录。

## 当前的保守降级

现有 runner 在可被其它协作者修改的工作目录执行任意 shell 命令。Git 树既不能证明命令执行期间没有发生内容切换，也不能覆盖忽略配置、依赖、构建产物、子模块脏文件及外部输入。因此当前登记的输入协议明确为 `mutable-workspace / unverified`，测试前后 Git 快照仅用于诊断。

当前清单协议为 2，输入策略为 `immutable-closed-inputs-required`。由于现有执行方式不具备不可变、闭合的实际输入证明，所有现有记录的 `reusable` 都是 `false`，包括 Git 树相等、退出码为零的记录。旧记录缺少输入证明时同样降级。`passed` 仍准确表示该次命令的实际结果，不表示它验证过当前版本。这次修复没有引入隔离 runner，也没有把调用方自报的输入范围当成完整输入闭包。

## 清单生命周期

自由审查、就地验证与历史独立审查在首次进入、续跑时生成诊断清单。异常重试先生成完整审查协议，再发送缩略续跑消息。结论上报与结算只核验本轮持久化的依据，不再重新生成、扫描全部历史执行日志。合并结果审查没有任务分支复用资格，也不写空清单。

`regression_evidence` 按服务端确定的轮次目录保存证据代次、撤销事实、该代次之前的执行 id、已接收的独立依据以及材料不可用的实际原因。撤销只增不减，清单刷新、删除、改写、请求重试、MCP 补录及服务重启都不能将同一份无依据结论升级成有效结论。旧轮次首次接入且存在执行者历史记录时，因无法证明其旧结论未引用历史结果，同样保守拒收无依据的通过结论。

恢复通过使用 `report_stage.verificationBasis={kind:"independent",generation,monitorIds}`：`generation` 来自本轮提示、清单的 `verification` 展示字段或拒收响应；检查由本轮 `start_monitor` 真实执行、完整正常退出且退出码为零，没有提前停止条件。服务端校验本轮归属、排除该代次之前的执行，并持久保存执行身份和完整日志摘要。上报与补录携带相同依据，结算再校验已接受的依据；仅重读清单、重复上报、更新报告不构成新执行。此凭据只说明本轮实际做过哪些独立检查，不授予执行者记录跨版本复用资格，也不替代审查者选择完整验证范围。

诊断清单 I/O 故障与旧引用撤销分开记录，不否定不依赖它的独立验证。独立执行依据本身暂不可读时，上报保留实际错误并返回可重试的 503。结算在读取材料前持久保存本轮真实退出结果与待恢复状态；已观察到的失败不会因后续重试变为成功。异常结束的审查不依赖证据读取即可收尾，独立测试通过并不代表审查回合正常结束。

正常退出但依据暂不可读的审查保留原结论、依据与轮次，不虚构测试失败。恢复可读后，自由审查、就地验证和历史独立审查的启动期对账使用已保存的退出事实重新核验；没有退出记录的遗留轮次不会仅凭任务终态或已有结论推定成功。轮次展示也使用该事实，不再以原任务的终态替代审查结果。

中断恢复同时发现尚无退出记录的持久验证轮次、历史审查证据及已有的待结算记录。被打断的回合先记下异常退出，再恢复任务原终态；就地轮次的计数、轮次清除、错误阶段撤回与结算提交共用事务。结算记录中的 `pending:false` 表示数据库业务状态已落位，同时保存的 `finalization` 是事务外收尾的持久待办，并不表示文件、清理和投递已全部完成。启动扫描和运行期重试分别处理这两种待办，一条失败不阻塞其它轮次恢复。

结论文件、哨兵回收、合并结果临时工作区清理及事件/时间线按步骤恢复；修复预约和确定身份的待发送消息在同一事务写入，重复恢复不产生第二条修复消息。后续工作流保存逐站完成记录；执行中断后无法确定副作用的站保留待处理记录并给出时间线说明，不自动重复执行。新的明确执行方向使旧自动推进失效，不覆盖新回合的阶段或预约。

轮次启动时保存目标的 turn、direction 与单调 epoch；真实审查续跑在起跑事务中转交该身份。退出记录继承原身份，不从恢复时的目标行重新取得权限。缺少身份的历史记录只完成自身结算；阶段、游标、提问、逐站运行占位、自动验收及修复消息消费均以原身份校验。已启动的命令可能继续结束，但方向变化会撤销后续站，持久收尾标记为 superseded；不会自动重复无法确认的外部副作用。修复消息在扫描、取得回合占位与真正启动前分别核验，更新方向或验收后的旧消息取消并留下持久记录。

轮次记账以原轮次号 CAS 释放 `verifyRound` 并递增计数，不依赖修改目标的权限；较新的轮次不受影响。历史方向身份缺失时，阶段、工作流完成站及游标保持原样，时间线说明「本轮结论未应用」。这类轮次的等待或检查点不能恢复成有权限的审查：续跑入口与恢复扫描将终止事实持久化，按轮次、方向、检查点文字和占用代次校验后，在同一事务清理原检查点及本轮提问、候选答案和问题列表；已有真实退出结果与答复历史仍保留。时间线说明「原提问随本轮终止失效」，过期答复不会转入实现会话，任务可重新派发审查。后续记账或时间线故障由待结算记录继续恢复，不把无法投递的旧等待永久留在排队状态。

轮次的 continuation 保存运行、等待、答复待投递和真实退出阶段；任务行的 waitOwnership 独立保存问题占用身份、检查点代次及普通/审查来源，不依赖审查证据行仍然存在。检查点取走及退回不改变归属，轮次终止即使看到空槽也会作废本轮代次，消息账本及手动续跑持有的旧凭证因此不能回填。新问题（即使文字相同）有新的占用身份，旧问题的答复 CAS 不会命中它。

审查起跑事务持久保存并返回本轮占用凭据，最终检查只核验权限，实际启动并交付输入后才移除待起跑标记。末尾权限撤销时，以该凭据关闭自身运行状态、等待及退出账本，不修改更新后的目标。单纯冻结或末尾存储读取失败则撤回启动，原答复继续处于 delivery、检查点继续等待；这不是审查失败退出。撤回落库临时失败时，恢复器凭待起跑标记和原身份重试，不因残留 running 而跳过；活跃运行占位仍受保护。后续工作流的失败提问显式记录普通来源，普通检查点和问题答复也按来源选择实现会话，不按旧 reviewing 历史选择审查会话。

审查工作流自身完成 merged/accepted 时，与阶段同事务保存限定该次收尾和原方向的验收交接凭据；普通旧审查权限仍不能操作已验收任务。验收后的命令、预览及游标推进沿用同一份逐站账本，不再从 human 锚点另算尾段。已完成的站不重复，失败或执行中断的站保留可见待处理记录，再次验收可明确补跑；异步验收前置命令通过后也接回原账本。换方向、外部验收或归档会撤销这份权限。

接力只传输问题与检查点的普通/审查/未知语义，不迁移原机审查权限。接收侧重新生成问题占用身份及本机检查点代次；安全移回时递增原机代次，使旧在途凭证失效。明确为普通来源的等待在迁移后仍可消费；审查等待保留来源但没有本机授权，提示重新派审，不转成普通实现指令。旧版缺少整个 waitOrigins 对象或其中单项时均持久保存 unknown 并提示重新派审，首次导入与安全移回采用相同语义。

等待字段或待投递答复只在原审查方向仍有效时保护轮次；正常结算、异常退出及恢复共用终止事务。普通回合开始前保留旧等待来源，新回合 writer 即使遇到缺失的审查证据行也会写下普通来源，因此后续旧审查终止不会删除它。升级存量中没有独立归属的审查等待按未知来源失效处理，不借用当前字段取得审查权限，也不将未知或已关闭审查的问题答复降为普通指令。等待归属不授予结论或工作流权限。

审查答复的历史记录、清问题、入队与待投递身份在同一事务中提交；答复带着该 evidence generation 和消息身份进入消费端。恢复与答复接受、起跑和结算使用同一写事务协议，待发送及持有投递租约的有效答复都不会被判为异常退出；失效答复被拒绝时同时触发原轮次收口，不退化成实现指令。这也适用于先上报结论再提问或暂停的回合。就地、历史独立、自由及合并结果审查共享此判据。

检查点按持久来源选择消费路径，审查或未知来源即使没有本机活动审查标记，也不会退回普通 resume/fresh；拒取或竞争失败会释放自身占位。接力消息携带 origin 及审查轮次元数据，但不会把源机审查绑定变成本机授权：审查答复、修复及来源缺失的历史消息导入或移回后被隔离，投递时取消并留痕，需重新派审或重新提交。明确为普通来源的消息正常投递。

受审查权限约束的起跑在任务自身保存身份及起跑前状态，包含审查结算后派生的普通实现角色修复。实际起跑交付后才移除记录；撤回和中断恢复只按该次身份释放持久运行状态。修复撤回不改写已经落定的审查账本，也不撤销归档、验收或替换方向。合法冻结前已接管的修复消息保留自己的方向交接凭据，只对同一条仍待发送的消息有效；恢复不会重新采样当前方向取得权限。

手动运行、重试及检查点续跑的持锁预检查共用异常释放保护：接管前读取失败归还原占位，迟到异常不释放替换回合的占位。运行路由已返回启动确认、但随后预检查失败时，时间线保留启动失败与可重试说明，数据库恢复后可以再次运行。

HTTP 上报及 MCP 补录使用同一事务入口保存结论与独立依据；提交时重验轮次、证据 generation、回合和方向身份。任一写入失败，两项一起回滚，事件与时间线只在事务提交后发布。进入结算后，相同结论与依据可幂等重试，不能改换结论或依据。

活动审查作用域与历史展示查询分开：就地验证使用当前 `verifyRound`，历史独立审查使用调用来源所属的活动审查及其回合/方向身份。HTTP 使用来源任务标识，MCP 补录使用原会话的来源任务；已完成的历史审查不冻结后来的普通阶段上报。

用户显式重开异常结束的自由审查时，同一事务清空该次结论并轮换证据 generation；旧退出结果与旧依据不带入新尝试，既有撤销事实保留，先前执行进入排除列表。普通自动恢复不会做这一重置。

证据 JSON 不是授权来源：原始字段以数据库为准，日志摘要独立校验；读取旧 JSON 只用于撤销可能遗留的授权，不会授予新资格。

旧表迁移在数据库写事务中按原始插入顺序补齐代次，保留已有字段，输入证明保持空值。新登记使用 SQLite `AUTOINCREMENT`，删除历史和进程重启不会让已分配的代次回退。
