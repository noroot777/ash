# 回复派生与任务侧聊

2026-09-11

## 本次实现

普通任务已结束的回复尾部增加「派生新任务」。点击后打开现有的新建任务面板，冻结原始任务正文、所选回复及之前的对话正文、已记录执行摘要和附件路径。面板可以展开核对快照，填写新的要求，再选择执行器、工作目录与创建方式。

快照按页面消息顺序截到所选回复（包含该回复），不带之后的消息；文本不做长度裁切。面板显示历史体积，最终派生正文（含本次指令）上限 128 KiB；超限时保留预览但阻止按钮和快捷键提交，可选择更早的回复或新建精简背景的任务。它在点击时生成，之后来源会话继续输出不会改变它。流式输出尚未结束、会话读取失败或正在刷新时不提供派生操作。

创建复用已有任务 API，快照成为新任务的正文，`originTaskId` 提供持久来源回链。新任务没有旧会话的 CLI session、完成状态、队列归属或执行进程；新要求与历史背景明确分开。派生草稿单独存放，不混入或覆盖项目已有的新建草稿；创建失败时保留草稿。

回复派生范围：网页普通任务会话中的回复派生。带入的是 ash 已保存的正文、执行摘要和附件引用，不是供应商内部隐藏状态或完整工具输出；附件文件和代码目录仍使用现有文件，并未回滚到回复时刻的版本。执行器和工作目录在新建面板按现有选项选择。草稿沿用当前应用会话内保存的机制，刷新前创建出的任务才已写入数据库。

## 任务侧聊与回传

任务顶栏增加「打开侧聊」，右侧 Inspector 中也有侧聊入口。可以连续追问、更换执行器、新建多段侧聊、切换记录、独立停止。关闭面板只收起视图；消息、停止状态和回执保存在数据库，草稿和当前选择保存在浏览器本地。主任务状态变化不抢走侧聊焦点，窄屏以右侧面板覆盖展示。

每段侧聊创建时读取主任务正文和已保存的用户/智能体会话正文，冻结后单独累积侧聊历史。主任务后续内容不会自动倒灌；需要新背景时新建侧聊。快照不含隐藏推理、CLI 身份、系统状态行或完整工具结果；附件保留正文中的路径引用。长历史复用现有预算和摘要机制，分块整理并保留原文，不静默裁掉前文。新侧聊快照按序列化后的 UTF-8 体积限制为 64 KiB，创建前展示上限与首次整理的等待/用量提示；超限返回实际体积，不创建房间、不调用摘要，也不截断原文。源正文及文件另有 4 MiB 读取上限；已结束会话正文缺失也会报错。这个上限换取可控的首次整理成本，当前尚未共享不同侧聊的摘要，大任务可新建简短任务填写精简背景后侧聊。

侧聊使用 ash 已配置的执行器，只读咨询通过现有聊天调用与工具事件检查。读取代码时复用任务文件浏览器对实际工作目录的解析，优先使用主任务会话的 cwd，不创建或删除 worktree；文件是当前版本，不是会话时刻的代码快照。侧聊不直接执行修改或继承主任务完成协议。因为主任务会在同目录正常写入，侧聊不挂目录变更观察器；可归因的写入/未知工具事件仍被只读闸门中止。

例如在侧聊中说：**「把刚才的结论告诉主任务，后续按方案 B 做。」** 智能体整理用户要求回传的结论，ash 将它投递给该侧聊绑定的唯一主任务，不必复制粘贴、切换聊天或再次确认。只回传这一份结论，不倾倒整个侧聊历史。模型不能指定另一任务；当前用户原话中的发送要求需要通过服务端核验，历史授权、引用、否定、假设或功能问题不会作为发送授权；模糊表达会显示未发送原因和明确表达示例。逗号后正常补充、发送对象中的引号以及整句复制的示例引号可以识别；附带条件时仍保守拒绝回传。回传拒绝、格式错误、归档或接力锁定都不作废已生成的回答：正文与模型历史照常保存，独立的“未发送到主任务”原因持久展示，且不加入投递队列。

侧聊提出回传后，ash 先核对授权原话逐字来自当前消息，再用所选侧聊执行器做一次独立语义核验。核验只收到整条当前用户原话，不接收侧聊历史、助手拟发送正文或截取的授权片段；只有明确判为“现在发送”才入队。核验在独立临时目录运行、不携带主任务身份，工具事件被拒绝。普通回答不增加核验调用；回传增加一次调用及其等待/用量，最长 45 秒。错误、超时、格式无效或含义不明都保留回答并显示未发送，不自动降级为词表放行。语义准确性依赖所选执行器模型，实测样本不代表所有模型和措辞都不会误判。

回传复用 `scheduled_messages`：侧聊回复和待发送消息在同一事务中保存，用回复 ID 生成稳定的消息 ID；同一客户端消息重试不会重复创建回传。主任务支持 native steer 且满足投递条件时立即接收；否则保持排队，不走强制 kill/resume 的降级路径。主任务空闲时由已有续跑链路发送。已归档、接力锁定、失去权限的任务不会接收新的回传。

主会话和待发送托盘中有「来自侧聊」来源文字；侧聊中持久显示「已排队／正在投递／已送达／已取消」回执，可展开查看实际正文。回执按队列真实状态更新，不把模型说的“已发送”当作送达证据。停止只取消尚未完成的侧聊回复；此前已提交的回传保留，可在主任务待发送消息里取消。数据库重启后，未完成的侧聊显示已中断，已提交回传沿现有队列恢复。删除父任务时停止侧聊执行器，并清理房间、消息、冻结上下文、摘要、整理状态和清空标记；迟到的摘要或请求不会重新生成孤儿数据。

取舍：先交付普通任务中的持久侧聊和自然语言回传；本轮未加入 `/btw`、选中文字提问、未读徽标或供应商原生完整会话分叉。侧聊回复目前在生成完成后展示，运行时显示进度状态。实时接收依赖执行器实际能力，排队回执不表示主任务已经执行；主任务沿用现有队列的崩溃恢复语义，在“供应商已收到但本地尚未记账”的极小窗口中可能重投，不声称跨进程绝对 exactly-once。

## Codex 的 Side chat 是什么

官方 [Commands](https://developers.openai.com/codex/reference/commands/) 列出独立的 **Open side chat**，macOS 快捷键为 `⌘⌥S`。[Projects and chats](https://developers.openai.com/codex/projects/) 中的 Quick chat 则是普通 ChatGPT 快聊，和这里的 Side chat 是不同入口。

为核实官方页面未说明的行为，本次只读检查了本机 `/Applications/ChatGPT.app/Contents/Resources/app.asar`，版本 **26.901.51231**。以下是安装包实现证据，不代表逐项完成了真人界面实测，也不保证其他版本或账号完全一致：

- 右侧面板里的临时分支会话。菜单描述为 “fork a local chat into an ephemeral right panel side chat”，创建链路使用 `thread/fork`、`ephemeral` 和 `sideConversation`。
- 继承主会话历史后，调用 `thread/inject_items` 注入单独的上下文边界，声明旧历史只是参考、新消息才是本侧聊要处理的要求，避免继续执行主任务。
- 默认用于问答和轻量、非修改式探索；本机边界提示禁止操作子智能体，只有新的明确要求才允许局部修改。代码复用了来源工作目录，所以它不是一份独立的历史代码快照。
- 支持从选中文字进入 “Ask in side chat”，也有 `/side` 入口；已有侧聊中不允许再用 `/side` 嵌套侧聊。
- 有独立未读提示、编号标题、关闭确认和过期状态。本机中文文案明确写明“侧边聊天是临时聊天，关闭应用后会消失”，关闭确认也说明会删除且无法恢复。

安装包还提供 `send_message_to_thread`，描述为向现有线程发送后续 prompt，并在目标任务显示为用户可见消息。侧聊的 `sideConversation` / `forkedFromId` 用于定位主线程，再进入 `sendFollowUpMessage`。这里的“无感”指不需要手工切换和复制，消息仍然留有记录。

定位证据：安装包 `webview/assets/app-initial-cadb12d4a15e.js` 的 `sideConversationBoundaryItems`、`thread/fork` / `thread/inject_items`；`app-primary-6cd7b8b3f5e3.js` 的侧聊入口与选中文字入口；`zh-CN-5bff6daefa6d.js` 的 `localConversation.sideChat.*` 文案。

## 实现复杂度

难度中等。复用 `InspectorHost`、执行器选择、ChatService、历史整理与既有消息投递，新增父任务绑定、历史快照、侧聊协议、事务回传和持久回执。主要复杂度在上下文隔离、停止竞态、真实送达状态和多用户权限，界面本身改动较小。

本次抽出任务 Inspector 描述与聊天路由访问检查，修改后的代码文件均低于 700 行。原生 steer 新增可选的 `nativeOnly`，旧的手动引导行为保持原样，侧聊只使用原生路径或队列。

### 第 2 轮审查修复

- 既有合法说法继续覆盖：逗号后“以后都按这个来”“说一下怎么改”“等它跑完再看”“比如先补一版验证”、带引号方案名、整句复制示例以及中英文直接发送要求。更复杂或混合疑问的表达可能被保守拒绝；用户可以另发一条清晰的发送指令，不会自动投递模糊要求。
- L2：派生历史按快照对象缓存 UTF-8 体积，输入时只编码本次指令与短包装文本。180 万字节历史连续模拟输入 100 次，没有重复编码整份历史；快照正文改变时缓存重算。
- P2 的产品取舍：本轮保留 64 KiB 新侧聊快照上限，超限主任务仍无法直接创建侧聊，需要先提供精简背景。审查的原始记录样本中约 2.8% 超过 64 KiB；实际创建还包含任务正文和序列化开销，这个比例不等于产品可用率承诺。本轮选择维持可控成本及完整快照，不新增“最近历史 + 摘要”机制；这是无人值守修复中的保守取舍，没有声称已取得用户对这一限制的确认。
