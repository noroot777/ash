# 主会话选文侧聊

2026-09-14

在普通任务主会话中选中文字，点击浮出的「在侧聊中提问」，即可打开侧聊并带入选文。键盘选文后按 Tab 可聚焦入口，Enter 打开；Esc、点击外部或滚动可收起入口。

侧聊显示「来自主会话」引用卡，原文可完整滚动查看，也可移除。已有侧聊的问题草稿保持原样；重新选文会替换当前引用。选文入口与 Inspector 入口现在都直接显示输入框，底部可修改执行器、模型和智能水平；首次发送时才创建侧聊。点击入口本身不调用模型，详见[直接提问交互](side-chat-direct-entry.md)。

引用与问题一起保存为侧聊消息：引用逐行使用 Markdown 引用标记，并与「当前问题」分开。这也能把侧聊创建之后主会话新出现的内容带入当前侧聊。主任务继续运行，消息仍使用既有侧聊接口和回传授权核验。

引用草稿按侧聊保存在浏览器本地，未创建房间时按主任务的新侧聊草稿暂存。关闭重开、刷新、切换侧聊或任务后可恢复；引用不会进入另一主任务。服务端确认收到用户消息后清理本次引用和对应问题草稿。失败保留待重试内容，重试沿用消息编号；发送期间新选的引用不会被旧回执清掉。

范围与取舍：本次接入网页普通任务的主会话正文，不包括主回复输入框、侧聊正文或其他面板。单次保留一个选文引用，使用用户当前选中的可见文本，不还原原始 Markdown。引用、包装文字与问题合计沿用消息的 8000 字上限，超限时提示并阻止按钮和 Enter 发送，保留完整原文；新建侧聊沿用既有的 64 KiB 历史快照上限。

浏览器通道：先尝试 Chrome 扩展具名后台会话「🔎 ash 选文侧聊验证」，返回 `unsupported Codex auth method: apikey`，无法建立扩展标签。因此验证使用独立临时 profile 的无头 Chrome（`headless: true`）。未激活、接管或直连用户普通标签，未启动有头浏览器。侧聊回归使用隔离临时数据库、真实 HTTP/SSE 和模拟模型，不向用户真实主任务发送测试消息。
