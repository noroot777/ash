# 任务运行环境

任务页可以同时显示会话和共享浏览器。这里展示的是服务器上同一浏览器会话的画面，不是另开一个同地址的 iframe；输入、滚动、页面内状态在用户与智能体之间共享。

## 服务

`start_dev_service` 在任务实际工作区运行启动命令，复用已有预览的动态端口、健康检查、日志和进程身份管理。同任务、同命令且端口可达时复用已有服务，不重复拉起；更换命令时替换此任务原有的开发服务。普通预览已经占用任务预览时返回冲突，不自动替换。

就绪后，任务页右栏冒出「服务」一格：服务名、状态、地址、启动命令和完整输出，面板头上是「在浏览器里看 / 打开 / 停止（或重启）」。智能体完成、续聊或任务重新执行后，开发服务及共享浏览器仍然保留；更换启动命令、验收清理工作区或显式停止时由现有预览生命周期回收。刷新后仍可辨认已停止、启动失败和启动中的状态。断开共享浏览器或切走、关掉那一格都不会停止服务。

普通的「预览指正」仍保留执行期间不能启动的门禁；执行中的开发验证是独立入口，并核对调用方的任务、当前回合和方向身份。已丢失的独立工作区不会降级到主仓库执行命令。

MCP 调用示例：

```json
{"taskId":"当前任务","directionToken":"当前方向","name":"Demo","command":"npm run dev -- --port $PORT"}
```

## 共享浏览器

`browser_action` 的 `open` 打开当前任务托管服务；`snapshot` 返回正文及可操作元素的 `ref`。`click / fill / select` 引用最近一次快照，后续操作携带返回的浏览器 `id`，`screenshot: true` 同时返回图像。导航、滚动、键盘和视口切换也走这一个会话。

右栏「浏览器」一格按需读取同一页面的画面；它是宽格，选中时跟会话大约五五开（可拖，双击回到一半）。智能体开出一个新的浏览器会话时右栏自动切到这一格，每个会话只切一次，切走后刷新也不再拽回来；窄屏不自动切。打开或重连浏览器默认为观看，不改变智能体的控制权。用户点「接管」后，智能体的修改操作被拒绝，已经排队的旧操作失效；进行中的单次操作结束后接管完成。用户可点击画面、向已聚焦的输入框输入文字、滚动、导航或切换手机尺寸；「交还」恢复智能体控制。

浏览器关闭、连接失败或服务器重启后，最后画面和操作记录仍可查看，但不会假装浏览器还在线。浏览器空闲 30 分钟自动关闭；服务不因此停止。服务回收时同时关闭它的浏览器。服务器最多同时维护 4 个任务浏览器。

## 边界

- 当前阶段只覆盖任务 Web 服务的浏览器操作，不镜像 Codex / ChatGPT 的专有浏览器宿主，也不控制桌面全局 CUA 服务。
- 浏览器使用隔离的临时上下文，不共享用户日常 Chrome 的登录信息。页面导航限制在此任务服务的源内；新窗口、下载和页面原生弹窗不作为交互入口。
- 服务器使用已有可选依赖 `playwright-core`，优先尝试本机 Chrome、Edge，再尝试 Playwright Chromium。可用 `CHROME_BIN` 指定路径；缺少依赖或浏览器时，失败原因会留在任务页，而不是报告验证成功。
- 此能力由上述 ash 工具提供。旧任务的 shell 后台进程、外部 Playwright 会话和 Codex 私有浏览器不会被追认为已托管资源。
