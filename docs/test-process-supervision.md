# 测试执行域

`scripts/test-process.mjs` 的结果边界包含根进程状态、双流与非保留工作的退出。Windows 由原生 Job 提供整域退出证明；macOS/Linux 保留 main 的可观测监管及其支持形态限制，不声称任意后代都已退出。

## 原生后端与支持边界

Windows 后端使用具名 Job Object。全部根命令（包括 Node）通过 `PROC_THREAD_ATTRIBUTE_JOB_LIST` 在创建时原子加入 Job，并以 `CREATE_SUSPENDED` 保持挂起，握手完成后才恢复，早于运行时初始化、用户 preload 和业务脚本；没有先创建一个域外进程再追认归属的窗口。后代自动继承 Job，未启用 breakaway。退出清理由 `TerminateJobObject` 与零活动进程计数确认，不依赖 PID、进程组号或历史父子号。

每个域有一个持有 Job 句柄的监督进程，并持有创建者的原进程句柄。创建者意外退出时，监督进程终止 Job；监督进程自身意外退出时，`KILL_ON_JOB_CLOSE` 关闭整域。监督器仅以创建者句柄和内核停止事件决定生命周期，不因诊断目录消失或短暂不可读而杀死业务。加入与终止共用内核互斥量和停止事件，避免清场后又加入一个晚到的根进程。

macOS/Linux 默认使用 `test-process-posix.mjs`，保留 main 的登记、父子链、活组长绑定、环境段和无名边界 inode 枚举；终止只用活句柄、活组长或实例自退通道。主动关闭边界、清空环境、setsid 并重新挂父的后代可能不可观测；可观测但无安全终止绑定的进程明确报错。具体支持形态沿用该文件的说明，不再默认在启动前以 `EOWNERSHIP` 拒绝业务。

Windows 首次使用时通过系统 PowerShell 的 `Add-Type` 编译小型 .NET Framework 监督器，不新增 npm 依赖，也不安装系统组件。编译不可用或 Job 分配失败时，调用明确失败，不退回扫描式清理。

## 登记、保留与回收

登记统一沿用 main 的 `<被登记 pid>.<发布者 pid>.json` 协议：父进程占位与子进程自登记分别原子 rename 到各自文件，读取时按 pid 归并，保留脚本、双流、自退通道等信息。不保留本任务原先的单份不可变记录方案。

`preserveScripts` 沿用 main 的指定脚本和独立双流判据，只从当前后端实际观察到的进程中返回 `preserved` 实例凭据；`terminateInstance()` 按凭据走 main 的实例绑定终止。成功结果额外保留 `dispose()`，可关闭原执行域并释放资源；`spawnTestFixture()` 的 `dispose()` 具有相同语义。Windows 域级清理按原 Job 对象执行，生产重启对不可读后代和 agent 子树的选择性保留不变。失败的清理保留域目录与诊断。

新建输出目录和域目录均位于事务保护内；域构造写入失败会回滚自有目录。每次新建域同时生成 256 位随机凭证，记录于独立的私有 `ash-test-owner-*` 目录，绑定域路径与原目录设备号/文件号。凭证不放在会被递归清理的域目录里，部分删除即使丢失全部域元数据也不丢失归属证明。域回收成功后才删除凭证记录和空凭证目录；初始化失败时两份自有目录均回滚。

恢复既有域从本进程登记表取得原凭证，或显式传入包含 token、独立记录路径及两份目录实例身份的 `directoryOwnership`。记录内容、随机 token 与目录实例全部匹配后才接受；数字 started、domain.json 的字段形状、临时目录名字或复制到域目录里的凭证文件均不作为授权。退出清理的 stdin 待办表和 CLI `--scopes <JSON数组>` 一同携带该凭证；只传裸目录路径的 argv 调用不能清理现存目录。恢复失败不删除或改写该域，读取权限错误及损坏的域描述仍明确失败。持久或内存中的 Job 身份仍被保留并查询，不由目录凭证代替内核身份。

执行域路径不可改写；构造记录目录的设备号和文件号，停止标记写入、递归回收以及退出清理子进程均核对原目录实例。目录已经消失可幂等完成，但后来替换成另一目录或符号链接时拒绝写入和删除。拒收的目录不进入退出清理登记表。目录归属校验与内核 Job 生命周期判据分离，不用「路径看起来已不在」推断 Job 已退出。POSIX 退役后清空边界身份，重复停止不再扫描已经释放的 inode，旧对象的递归回收仍核对路径实例。

`domain.json` 在监督进程就绪后才发布；启动失败或握手超时先用原监督进程句柄阻止迟到的初始化，再终止并确认 Job 消失，回滚元数据。无法确认回滚时保留原始错误、域身份和诊断。原生 `state` 查询区分内核对象不存在与查询失败；本地 `closed` 文件或目录是否存在不再是内核退役判据。域已经被其他清理者退役后，重复 `active()`、`stop()`、`remove()` 均可幂等结束；目录先消失时，退出清理仍携带内存中的 Job 身份，而不是丢掉尚存的内核执行域。

退出清理按执行域记住已经失败的尝试：重复隐式清理返回原诊断，不再次执行同一域的清理，也不阻止后来创建的其他域退役。仍有未退役域时保留其原生工具和诊断目录，全部域退役后才释放编译产物。业务断言与清理异常会汇总，其他临时资源的回收不会因前一项失败而跳过。原生进程列表遇到出生/退出抖动时使用 10ms 退避和 5 秒有界窗口；仍无法确认时维持明确失败，不把不完整快照当作清场证明。
