# 测试执行域

`scripts/test-process.mjs` 的结果边界包含根进程状态、完整双流与所有非保留后代的实际退出。Node 自登记仅用于识别可保留脚本，不再用于证明进程所有权或决定终止对象。

## 原生后端与支持边界

Windows 后端使用具名 Job Object。全部根命令（包括 Node）通过 `PROC_THREAD_ATTRIBUTE_JOB_LIST` 在创建时原子加入 Job，并以 `CREATE_SUSPENDED` 保持挂起，握手完成后才恢复，早于运行时初始化、用户 preload 和业务脚本；没有先创建一个域外进程再追认归属的窗口。后代自动继承 Job，未启用 breakaway。退出清理由 `TerminateJobObject` 与零活动进程计数确认，不依赖 PID、进程组号或历史父子号。

每个域有一个持有 Job 句柄的监督进程，并持有创建者的原进程句柄。创建者意外退出时，监督进程终止 Job；监督进程自身意外退出时，`KILL_ON_JOB_CLOSE` 关闭整域。加入与终止共用内核互斥量和停止事件，避免清场后又加入一个晚到的根进程。

当前没有实现可证明上述契约的 macOS/Linux 后端。这些系统在启动任何测试命令之前返回 `EOWNERSHIP`，回收已经创建的目录，不再把扫描不到后代报告为成功。**因此这些系统上的完整 `npm run test:restart` 当前会明确失败，而不是跳过后代断言后报告通过。** 所有权自测仍可验证这条拒绝边界和初始化回滚。这是安全性优先的显式能力限制，不是两平台完整业务回归通过。

Windows 首次使用时通过系统 PowerShell 的 `Add-Type` 编译小型 .NET Framework 监督器，不新增 npm 依赖，也不安装系统组件。编译不可用或 Job 分配失败时，调用明确失败，不退回扫描式清理。

## 登记、保留与回收

每个 Node 实例只发布一份随机文件名的不可变完整记录。临时文件写完并关闭后，以硬链接原子发布；父进程不再向同一文件发布占位记录。记录带 Job 标识、原生创建时间和两个输出文件身份。残缺记录、旧域记录或出生代次不匹配的记录不能保留进程。

`preserveScripts` 只保留当前 Job 中、创建时间匹配且双流均独立的指定脚本。成功结果的 `dispose()` 关闭原执行域并释放其资源；`spawnTestFixture()` 的 `dispose()` 具有相同语义。退出兜底按原 Job 对象清理全部剩余域；没有从旧号码重新恢复所有权的路径。失败的清理保留域目录与诊断。

新建输出目录和域目录均位于事务保护内；域构造写入失败会回滚自有目录。恢复既有域只读初始化信息，恢复失败不会删除或改写该域。

退出清理按执行域记住已经失败的尝试：重复隐式清理返回原诊断，不再次执行同一域的清理，也不阻止后来创建的其他域退役。仍有未退役域时保留其原生工具和诊断目录，全部域退役后才释放编译产物。业务断言与清理异常会汇总，其他临时资源的回收不会因前一项失败而跳过。原生进程列表遇到出生/退出抖动时使用 10ms 退避和 5 秒有界窗口；仍无法确认时维持明确失败，不把不完整快照当作清场证明。
