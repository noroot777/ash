现状

A · 书签 Tab

独立条贴在输入框左上角，border-bottom 与输入框咬合，左上圆角被压平。像浏览器页签 / 书签，视觉权重偏高，和底部工具行也脱节。

  • 书签形态本身就是吐槽点
  • 与输入框外轮廓咬合，圆角不完整
  • 位置显眼，新用户容易发现

推荐

B · 悬浮芯片行

彻底去掉书签咬合：三个 soft pill 浮在输入框上方，与输入框保持 6–8px 间隙，输入框四角完整圆角。动作区是「工具条」，不是「页签」。

  • 告别书签形态，最直接对症
  • 输入框轮廓干净、完整
  • 改动面小：只改 toolbar 布局/样式，结构几乎不变
  • 仍占一行纵向空间（与现状相当）

候选

C · 输入框内嵌顶栏

动作收进输入框内部顶部一条浅色轨，用细线与正文区分。整体是「一块控件」，不再有外挂结构。

  • 视觉一体化，外轮廓始终完整圆角
  • 不额外占 shell 外部高度（挤在 box 内）
  • 与输入区域抢纵向空间，长文时略挤
  • 容易被读成「当前模式标签」而不是「可点操作」

D · 并入底栏工具行

把三个动作塞进输入框底栏左侧（附件 / 定时右边），与执行器选择器同层。零额外高度，最「工具化」。

  • 不占额外纵向空间，输入框更干净
  • 和发送、执行器在同一操作平面
  • 底栏已经挤（附件/定时/执行器/提示/发送），窄屏会折行或溢出
  • 重要动作（合并）与次要图标混在一起，层级变弱

候选

E · 分段控件（segmented）

三个动作收成一组「胶囊分段控件」，浮在输入框上方。像 iOS segmented control / Linear filter，整体感强、颜色克制（色只在 icon 上）。

  • 成组感强，不再散成三个独立按钮
  • 和书签完全不同语言，辨识度高
  • 分段控件常被用于「互斥选项」，这里却是三个独立动作，语义略拧
  • 合并是破坏性操作，和审查/预览平铺在同一段里略冒险

候选

F · 极简图标轨

只保留带色底的图标按钮 + 悬停/焦点时显示文字（本 demo 用 title / 固定小标签双轨）。最省空间、最安静；适合已经熟悉产品的用户。

  • 视觉噪音最低，不抢输入框
  • 窄屏友好
  • 首次发现成本高，中文标签是产品优势被丢掉
  • 「合并&清理」这种重操作不宜只靠图标
