就地验证跑在同一条会话里，怎么让人一眼看出「这段是在审我」

现在的就地验证是搭在被验任务身上的旁路回合：协议正文渲染成系统代写消息， 审查者的产出渲染成一条普通 agent 气泡——跟它上面那条「我在做需求」的气泡长得一模一样。 换了执行器时只有执行器名不同，没换执行器时连名字都一样。 下面五个方案用同一份会话内容渲染，只有验证段的样式不同，可直接对比。

判据（按重要性） 起止边界清不清楚——验证段可能很长 滚到中段还认不认得出「仍在验证里」 会不会把会话变重、抢走正文的注意力 要不要模型层新给数据（段起止 / 单条标记）

A 只需要给气泡打一个「这条是验证轮」的标记，成本最低，且它和其余四个方案都能叠加—— 先把「谁在说话」说清楚。真正的痛点是长审查滚到中段认不出，那要靠 B 的段落容器补上。 B 需要模型层给出验证段的起止，但数据本来就有（verifyRound + 时间线里那两条「第 N 轮验证开始 / 结论」旁注），是推导而不是新采集。

D 留到「历史轮」再用

折叠卡对已经结束的旧轮次很值——三轮验证的正文能把主线淹掉； 但对正在跑的那一轮必须默认展开，否则用户盯着一张不动的卡片不知道里面在干什么。 建议规则：非最后一轮、且已有结论 → 默认折叠；其余展开。

C 和 E 的取舍

C 的缩进语言和现有「系统代写消息 / 旁注」的左竖线撞车，同一屏里三种左竖线会互相稀释， 不建议单独用。E 是 B 加一条吸顶段头，只在验证正文特别长时才回本； 会话区已经有任务头，再吸一条要盯住层级和贴底逻辑，建议 B 落地跑一阵子再决定要不要加。

配色说明：验证段统一用 --cyan，不用 --accent——靛蓝在这套界面里 已经被「你（真人）」占着（用户气泡、系统代写消息的左竖线都是它），验证段再用会把 「谁在说话」这条最要紧的线索搅混。结论仍走 --green / --red。
