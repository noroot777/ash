任务一多，侧边栏那一列只剩标题，得挨个点进去才知道该处理谁。 这张 demo 把同一份列表就地向右铺满：状态点和标题横向一格都不动（所以铺开像拉窗帘，不是换了个页面）， 多出来的横向空间依次写上走到哪一步、原始需求、最后一条消息。 看准了点一下就选中并收回原样，再按一次快捷键也收回。

右上角切行高来回比：等高 34 是跟现在列表一模一样的行高——铺开时行一点不长高，纯横向展开，代价是每格只剩一行、副标题（执行器 · 已跑多久）藏起来； 两行 62 把需求和最后一条消息各放两行，看得清楚，但同样高度只装得下一半的任务。紧凑 46 是中间档。 在这个 700px 高的 demo 窗口里实测：34 档一屏 13 行，46 档 9 行，62 档 7 行（真实全屏窗口按比例更多）。

三个刻意的取舍

  • 左边两列横向钉死。状态点 22px、标题列左边缘 22px 处起，铺开前后同一个横向位置；只有截断点从 214 放宽到 300，让标题多露出小半句。所以铺开是「露出右边」而不是「重排列表」，眼睛不用重新找任务；分区（置顶 / 协作任务 / 普通任务）和顺序也原样保留，跟 taskTreeModel.ts 现在的分组一致。行会因为多出的筛选条整体下移一点点，这段是有过渡动画的。
  • 「走到哪一步」写的是 stage 而不是 status。仓库里这两个是正交的：status 管调度（运行中 / 排队中 / 暂停中），stage 管验收进度（验证中 / 待验收 / 已合并）。铺开后一行能同时写下这两层，外加它在工作流里第几站、跑了多久——这正是窄侧边栏塞不下的东西。
  • 需要你拍板的行淡染成琥珀色（等答复 / 待验收 / 失败），并在顶上给一个「需要你处理 N」的筛选。不画左侧指示条——全局约定里选中态只用淡染背景。

还没定、想听你一句话的

  • 行高选哪档。右上角三档来回切着比。等高 34 跟现在的列表一个行高，铺开纯粹是横向展开、行不长高，眼睛完全不用重新适应，代价是需求和消息各只剩一行、副标题（执行器 · 已跑多久）藏起来；两行 62 信息读得清楚但同高度只装一半的任务。要是你多数时候只想「扫一眼谁需要我」，34 够用；要是想不点进去就把消息读明白，62 更合适。
  • 快捷键定哪个。demo 用了 F（铺开 / full）并兼听 \。现有裸键已占 j k c r，F 是空的；要是你更顺手 Cmd+\ 或空格，改一行就行。
  • 「最后一条消息」取哪条。demo 取的是会话里最新一条（不论谁说的），等答复时优先取那句提问。另一种取法是「永远只取最后一次追问 / 提问」，没提问就留空——更聚焦但空行会多。
  • 要不要记住铺开状态。现在每次都从收起开始。也可以像折叠分区那样写 localStorage。

真做进 web-next 的话，动这几处
