任务一多，侧边栏那一列只剩标题，得挨个点进去才知道该处理谁。 这张 demo 把同一份列表就地向右铺满：每一行横向、纵向都待在原处一格不动——行不长高、不上下漂， 只是右边多露出原始需求和最后一条消息。看准了点一下就选中并收回原样，再按一次快捷键也收回。 这两列一行放不下的，鼠标指上去弹一张全文卡片；带图的格子右端标着 ▣ 2，卡片里的图点开就是大图。

打开右上角的标尺：它会照着收起时每一行的上边缘钉一排红线，然后按 F 铺开—— 线不用重画，每一行仍然精确压在自己那条线上。为此让路的是两样东西：铺开时不再插入筛选条那一行（挪进了顶部本来就空着的地方），列名行去掉了。

四个刻意的取舍

  • 每一行原地不动，横向和纵向都是。状态点 22px、标题左边缘 22px 处起，铺开前后同一个横向位置（只把截断点从 214 放宽到 300，让标题多露出小半句）；行高恒定 34px，顶上也不新增任何一行，所以纵向位置也分毫不差。铺开因此是「露出右边」而不是「重排列表」，眼睛不用重新找任务。分区（置顶 / 协作任务 / 普通任务）和顺序原样保留，跟 taskTreeModel.ts 现在的分组一致。
  • 为了纵向不动，砍了两样东西。筛选条不再单占一行，挪进顶部项目名右边和图标那一行的空白里；列名行（走到哪一步 / 原始需求 / …）整个去掉——它一插进来，下面每一行就得下移 24px。所以列的含义只能靠内容自身认：最后一条消息前面有它说 / 它问你 / 正方这样的说话人，原始需求是更淡的那一列。
  • 需要你拍板的行淡染成琥珀色（等答复 / 待验收 / 失败），并在顶上给一个「需要你处理 N」的筛选。不画左侧指示条——全局约定里选中态只用淡染背景。
  • 放不下的不硬塞，指上去再给。34px 一行只够放一句被截断的话，所以剩下的都藏在悬浮里：指住原始需求或最后一条消息停 0.16 秒，弹一张全文卡片。卡片是 position:fixed 的，跟列表布局互不相干，弹出来一行都不会动；鼠标从格子移到卡片上也不会消失，所以卡片里的图点得到。带图的格子右端标 ▣ N（一眼看出这条有截图，不用悬浮试探），点缩略图开大图，←→ 翻页，Esc 只关大图、不顺手把侧边栏也收了。

还没定、想听你一句话的

  • 删掉「走到哪一步」之后，状态还够认吗。现在只剩左边那颗状态点（跑着的会呼吸、要你处理的是琥珀、失败是红），阶段文字（待验收 / 验证中 / 已合并）和「工作流 5/5」都没了；顺带一起没的还有标题下面那行执行器和耗时（claude · 已跑 6m）——34px 一行放不下第二行字。要是扫的时候还是想一眼分清「在跑」和「等我点头」，可以把 chip 挪回标题左边一格，不新增列、也不影响纵向。
  • 快捷键定哪个。demo 用了 F（铺开 / full）并兼听 \。现有裸键已占 j k c r，F 是空的；要是你更顺手 Cmd+\ 或空格，改一行就行。
  • 「最后一条消息」取哪条。demo 取的是会话里最新一条（不论谁说的），等答复时优先取那句提问。另一种取法是「永远只取最后一次追问 / 提问」，没提问就留空——更聚焦但空行会多。
  • 要不要记住铺开状态。现在每次都从收起开始。也可以像折叠分区那样写 localStorage。
  • 全文卡片是「指上去就弹」还是「按住 / 点一下钉住」。现在是悬停 0.16 秒自动弹、移开 0.14 秒自动收——扫的时候最省事，但鼠标横穿列表会一路弹。要是嫌吵，可以改成只有按住某个键（或点 ▣ N）才弹，代价是多一个动作。

真做进 web-next 的话，动这几处

  • web-next/src/workspace/WorkspaceShell.tsx：持有 spread 状态，传给侧边栏；点任务时顺手关掉。

  • 「最后一条消息」需要一个列表接口能带上的字段（现在的 Task 上没有），要么服务端在列表里补一个 lastMessage 摘要，要么前端按需拉。这块是唯一有后端改动的地方——顺带要带上附件缩略图（悬浮卡片里的 ▣ N 和大图靠它），demo 里这些图是现画的 SVG 假图。
