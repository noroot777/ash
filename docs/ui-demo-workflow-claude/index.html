桶只回答一句话：现在要不要我管

这一页说的不是分组（Group）那个容器，是侧栏按什么把任务归堆。之所以必须一起定：工作流一上线，任务能处的状态就变多了，侧栏不重新定义就会当场说胡话。今天「普通任务」摊开 8 个 TaskStatus 分组，加上工作流会变成十几个。方案是反过来：引擎内部可以很细，侧栏必须粗 —— 只有四个桶，精确态退到行内一个小标签，完整节点游标退到任务详情。不给 verifying / 预览中 再加第 5 个桶。

队列那一列压根不用改

四桶只影响侧栏怎么摆，不影响调度。队列仍然只看 TaskStatus：canceled 透明跳过、failed 留原地不拖链、awaiting_review 停住链等你。工作流没有给队列新增任何一种输入 —— 它只是让 awaiting_review 这一段变长了，而这是你自己开人工关口换来的。

图留下来，但只用来看，不用来编

同一份定义换个渲染：主干、失败边、有界回路、不可逆闸一眼可查。编辑仍然在第 ① 页的纵向轨上做 —— 因为真正天天在改的是开关和参数，不是拓扑；把高频操作藏在拖节点后面是反的。存储用的就是「节点 + 出口」的图形状，将来真需要放开画布，是放宽约束，不是改数据结构。
