线路 · 单个任务

一个任务，从左到右要停几站。

每一站是一道关口，站与站之间是一段线路。在两站之间加一站、拆掉一站、 把某一站失败后的车拐回上游任意一站 —— 都直接在线上做。下面四条是常跑的线路，不是仅有的选择。

线路图
为什么横着排

一个任务的关口链本来就是「一条线，偶尔往回拐」。横排把时间轴摆成线路， 谁在前谁在后一眼可见，往回拐的那几段是线下面的虚线支线 —— 不用连线、不用对齐、没有画布。

放开编排就必须有闸

能自己排，就排得出坏线路：合并前没人看、预览起了没人关、失败往前跳成死循环。 底下那条检查不是装饰，红的存不下去，并且指名是哪一站、为什么。

同一份定义，换个外观

这张线路图和 深色调度台、 句子 / 清单 / 规则表、 可拖拽工作台（带预演） 几副外观， 共用 ../ui-demo-workflow-kit/model.js 一份定义：一串关口 + 每关的参数 + 每关失败的去向。
