ash 界面审查 回报告

ash 的话，写成回复末尾的一句。

会话里占一行的只剩两种：你说的，它说的。ash 要告诉你的事——审查出了结论、验收了、没办成——接在它那条回复的正文下面，一句小灰字，不带图标。回复的头一行说它为什么开口，最后一行说它后来怎样。

会话末尾

你圈的第二处。三句话占三行，三种长相，比它最后那段结论还占地方。改后并成一句。

现在 改后 指到时 点开记录

原来单挂在最后的那几条记录归到最后这条回复上，尾注里的两句也在里面，删除在每一条的后面。审查那半句照旧能点，去右侧审查格的那一轮。

两条回复之间

你圈的第一处。这四行是 ash 记的流水，本来就不该常显。它们冒出来，是因为现在记下的话不分种类，界面只能照字面猜：「哨兵已起：……」后面带着命令原文，里面有「失败」「错误」这样的字，就被当成出了岔子、标了红。改后不猜了，只有固定的几种说法上尾注，其余一律进记录。

现在 改后 那四条在

前一条回复指到时的「4 条记录」里。「终态被拦下，改为检查点暂停」说的是任务暂停了、在等哨兵——等的时候回复末尾已经有「在等哨兵」那一行。

颜色只说现在的事

尾注平时全灰，通过、已验收也不带绿。只有还没了结的坏消息，字前面有一颗小圆点：红是没办成，琥珀是等你拍板。后面一有新的回复，点就灭——审五轮不会留下五颗彩色记号。

哪句话去哪

  • 第 N 轮审查通过 / 未通过，N 条意见尾注；点了去右侧审查格的那一轮
  • 已验收，合并到某分支尾注，和审查结论并成一句
  • 这一轮异常结束、审查没能开始尾注，还没了结时带红点
  • 驳回了审查意见，等你裁定尾注，带琥珀点，后面跟「去裁定」
  • 哨兵已起、哨兵结束、改为暂停、合并完成、清理完成……只在「N 条记录」里
  • 审查正在进行不变，还是那张卡：审查者正在说话
  • 向你提问、合并冲突要你接手不变，要你动手的还是卡

没选的画法

两条回复之间拉一条细线、中间写小字，聊天软件里常见。没选它：线会把会话切成一段一段，哨兵那次你嫌的就是这个；它还把这句话挂在两条回复之间，可这句话说的是前一条回复的下场。
